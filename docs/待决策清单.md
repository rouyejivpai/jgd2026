## 决策 1：M5-1「底部信息栏」——做还是删？

### 现状

这条任务**在详设、需求文档、策划案里都找不到对应规范** —— 它是当初我列 54 项清单时自己加的。
（第 7 轮做过一次需求覆盖度审计，把 69 条 `FR-*` 逐条对照过代码，确认没有这条。）

它原本想承载"阶段 / 已用时 / 信号状态"，而这些**已部分被别的界面覆盖**：

| 想显示的 | 现在哪里能看到 |
|---|---|
| 关卡阶段（编制 / 推演 / 结算） | 工具条按钮的可用性差异（开始禁用 = 已进推演期） |
| 已用信标 n/N | 工具条右侧「信标 2/4」 |
| 无效指令数 | 工具条右侧「无效指令 1」 |
| 已用时 | **只有结算界面能看到**（明细里的"用时 x.x 秒"） |
| 各信号开 / 关 | **完全看不到** |

### 选项

| 选项 | 具体做法 | 代价 | 收益 |
|---|---|---|---|
| **A. 删掉这条任务** | 从清单里移除，54 项变 53 项 | 无 | 清单与现实一致，不再挂着一个"无依据的任务" |
| **B. 重新定义为「推演期状态条」**（我的建议） | 在工具条右侧再加两个只读标签：**已用时**（推演期才显示）+ **信号灯**（几个小圆点，开=亮）。不新增"底部栏"，只扩详设 10 §1.3 已经定义的「右侧状态」区 | 约 1 小时：UI + 用例 + 截图断言 | 补上两个**目前确实看不到**的信息：用时（解谜时很关键）与信号状态（第三关的核心机制，现在玩家只能靠猜） |
| **C. 照原样做一条底部信息栏** | 屏幕底部新增整条信息栏 | 更大，且要改详设 10 的布局图 | 我**不建议**：没有规范依据，且"底部栏"会与工具条的信息重复 |

> **我的建议是 B。** 理由：它不发明新布局（只是把详设已定义的"右侧状态"补全），
> 而且补上的两项都是**玩家现在真的看不到、且对解题有影响**的信息 ——
> 尤其**信号状态**：第三关叫「信号与协同」，而玩家目前无法在界面上看到任何信号的开/关。

## 决策 2：M4-7 存盘端到端——需要你在本机验一次

### 现状

代码**已通**（写盘 → 失败回退 `user://` → 维护 `manifest` → 保存前校验），
FR-TEST-05 的前半段**全部已验**：

- ✅ 新 id 不与现有三关撞车（`new_level_N`）
- ✅ `order` 排在最后
- ✅ 新建后 `dirty = true`（否则试玩会去载入一个不存在的文件）
- ✅ 内容往返逐字段一致（**真落盘**，写在项目外，17 字段 0 差异）
- ✅ 写盘失败时优雅报错且**不清 `dirty`**

### 为什么我这边验不了

第 13 轮我写了探针 `tools/probe_write.gd` 把"能写哪里"一次问清：

```
user:// 实际路径 = C:/Users/15335/AppData/Roaming/Godot/app_userdata/人工神灵/
写 user://__probe_root.txt          -> ❌ 打不开
make_dir_recursive(user://levels)   -> 返回 0（OK）      ← 但见下一行
目录是否存在                        -> false             ← API 说谎了
覆盖已存在的 manifest.json          -> ❌ 打不开
```

两个值得你知道的事实：

1. **`DirAccess.make_dir_recursive_absolute()` 会「返回 OK 但目录不存在」** —— 只信返回值会踩坑
2. **本沙箱的写权限跨运行不稳定**：第 8 轮同一个路径**写成功过**（编辑器的保存真的覆盖了
   `tutorial_01.json`），第 13 轮**连覆盖都不行**。所以"能不能写"的结论不能跨运行引用

### 本会话里已经查清（第 13 轮）

写不进去**不是"沙箱随机"**，而是**项目子目录在 Windows 文件权限上确实缺一项**：

| 对象 | 子进程能写吗 |
|---|---|
| `D:\jgd2026`（工作区根） | ✅ |
| `D:\jgd2026\_shots` | ✅（截图、探测文件都真的落盘了）|
| `D:\jgd2026\v0.0.1` | ❌ 缺一项权限 |
| `D:\jgd2026\v0.0.1\data` | ❌ 同上 |
| `D:\jgd2026\v0.0.1\data\levels` | ❌ 同上（关卡文件就写在这里）|

我已经对这三个目录各补了一次权限（**每处先备份、改完复核，三次都验证通过**），
修复后整套测试完好（975 项全绿、像素 243/243、真实关卡数据未被破坏），
**但写入仍然失败** —— 说明还有那个排查工具覆盖不到的机制。

### 你需要做什么

**最快的一条路**：把本会话临时切到「**完全权限**」(full access)，我再试一次写入。
若能成，M4-7 当场就能收口。

**或者**在你自己的机器上（不经过 DSH 沙箱）：
