## 决策 3（Q1）：编制期 cost 与召唤 —— 进不进范围？

### 现状
三关都是**关卡预置固定单位**（第一关 1 个 `standard`，第二关 1 个 `standard_attack`，第三关 1 攻击 + 1 冰寒），
没有 cost 概念；工具栏有「开始 / 重置 / 倍速 / 信标 / 视野 / 机制说明 / 关卡介绍」。

### v2 怎么说
「初始时，会给玩家发放一定的 cost，玩家可以使用 cost **召唤单位**，并编辑单位的行为逻辑」
「角色栏位：可以拖动以上场，cost 不够也能拖上去，但是消耗总 cost 高于总 cost 时，无法开始游戏，
会提示 cost 消耗超额。若角色之后过多，角色栏位视为可翻页」
还有「**清空**：清除所有我方单位，回到关卡开始」。

### 关键事实（决定选项的重要依据）
**v2 的三关新手教程仍然写「我方单位：基础人工生命」「我方单位：基础-攻击人工生命 冰寒人工生命」**
—— 教程关本身**没有改成 cost 制**，只有 3.1 主玩法与 3.2 操作说了 cost。

### 选项
- **A（推荐）教程三关保持预置单位，cost 系统留到第一章再按需求做。**
  理由：教程关的教学重点是"学会写指令"，一上来引入经济会分散注意；而且 v2 的三关参数没改；
  现在改会把"已在跑的三关数据 + 编辑器 + 22 张截图基线"全部翻一遍。
- **B 立刻改成 cost 制**：关卡数据加 `initial_cost` 与可召唤单位表，编制期加角色栏位/拖动/超额提示/翻页/清空，
  编辑器同步，三关数据迁移，回归全部用例。**这一条本身就是一次数据模型升级。**
- **C 不做**，记入 Phase 2。

## 决策 4（Q2）：信标改成「每个角色自己的」吗？

### 现状
**关卡级共享信标池 + 配额**（`beacon_quota`）：玩家在地图上依次放 1、2、3…号信标，
单位的行为「沿着信标移动」引用这些**全局序号**。配额用完就不能再放。

### v2 怎么说
「玩家可以选择放置信标，**每个角色有自己的信标，不可公用**，可以**框选角色然后批量设置**其信标。
相当于 rts 游戏设置角色路径。」

### 选项
- **A（推荐）先让数据结构支持 per-unit**：把信标序列挂到单位上（`unit.beacons`），
  渲染与指令面板按单位取；**UI 先只做单单位编辑**，框选批量留到后面。
  这样 v2 的语义成立了，但不至于一次性重写编辑器与结算。
- **B 一次性全改**：含框选批量设置 + 编辑器信标编辑 + 结算 Cost 口径 + 三关数据迁移。
- **C 保持共享池**（现状），把 v2 这条记为"后续版本"。

### 影响面（无论选 A 还是 B 都要动）
关卡数据 schema、信标层渲染、指令面板的信标引用、结算里的「Cost 消耗」口径、编辑器与测试。

## 决策 5（Q3）：要不要硬性「每条指令至多 1 行为 + 2 条件」？

### 现状
条件**数量不限**（超过若干条会**折叠显示**，这是 **D-20 明确进 MVP 的功能**）；
行为在数据结构上也是数组（可以加多条）。

### v2 怎么说
「每条指令至多有一个行为和 2 个条件。」

### 冲突
这条**直接推翻 D-20**（多条件折叠显示），并会删掉已实现并有用例守护的功能。

### 选项
- **A（推荐）加"校验提示"而不硬禁**：当一条指令超过 1 行为或 2 条件时，
  在指令面板上给出明确提示（黄条/角标），但允许存在。
  这样既表达了策划意图，又不推翻已确认决策、不删功能；等策划确认后再决定是否收紧。
- **B 硬禁**：UI 不允许加第 3 个条件/第 2 个行为，并**更新 D-20**、删折叠功能与相关用例。
- **C 忽略**，仍按现状。

### 顺带记录（不用你回答，但要知道我们怎么处理）
v2 3.3.2 还有一句「一次判定只执行一个指令……上层条件满足则下层即使满足也无法执行」，
**与它紧随其后的例子自相矛盾**（例子说"先执行 1 停火、再执行 2 开火，最终效果就是有敌人时开火"，
即**下层生效**）。我们按**例子**实现（同冲突键后者覆盖前者，需求 5.4），不按那句话的字面实现。

## 决策 6（Q4）：结算改成四项指标？

### 现状
**三项**：指令复杂度 × C1、信标成本 × C2、时间成本 × C3（`data/scoring.json` 里 C1=10、C2=10、C3=1，见 D-14）。

### v2 怎么说
「所用人数=所用人数×系数 / 指令复杂度=（行为数量+条件数量）×系数 /
**Cost 消耗=信标数量×系数** / 所用时间=所用时间×系数 / 将**四个**指标相加……越低越好。」

### 需要澄清的术语
v2 的「**Cost 消耗**」被定义成「**信标数量** × 系数」，
而 3.1/3.2 的「cost」是**召唤单位的花费** —— **同名不同义**。

### 选项
- **A（推荐）加第 4 项「所用人数」**，第 3 项维持"信标数量"口径（`scoring.json` 加一个系数，结算页显示 4 行）。
  改动小：`scoring.json` + 结算页 + 用例。
- **B 把「Cost 消耗」理解为"信标 + 召唤花费"**（需要先回答 Q1 是否做 cost 系统）。
- **C 维持三项**。

### 另需你一句话
「**所用人数**」是指**上场单位数**（当前是关卡预置，可直接数），还是**召唤花费的总和**？
