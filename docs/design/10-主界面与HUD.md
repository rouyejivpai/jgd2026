## 2. 系统边界

### 2.1 本系统负责

- 顶部工具条六个按钮的呈现与接线。
- 倍速控件的呈现（值来自 [01](01-时间与逻辑帧.md)，切换调 `set_speed_multiplier`）。
- 关卡介绍弹窗（自动弹一次 + 随时重看）与 tips 展示。
- 机制说明面板：读取并解析 `res://data/help/机制说明.md`，按标题分节切换。
- 结算界面：展示 `ResultData` 全部分项与出口按钮。
- 选关界面：读 `manifest.json`、展示关卡名、进入关卡。
- 主菜单新增「关卡编辑器」入口。
- 暂停菜单：继续 / 重置关卡 / 返回主菜单（**不含编辑指令**）。
- **信标模式**：工具条上的信标按钮、点格放置、右键撤回、序号显示、计数显示。
- **敌人视野辅助显示**：可开关的视野圆绘制（FR-TUT-04）。
- 无效指令角标的显示（数据来自 [09](09-指令编辑界面.md)）。

### 2.2 本系统明确不负责

| 不负责 | 归属 |

| 点开始后的实际逻辑推进 | [06 关卡数据与胜负条件](06-关卡数据与胜负条件.md) |
| 结算分数的计算 | [08 评价与结算](08-评价与结算.md) |
| 指令的编辑交互 | [09 指令编辑界面](09-指令编辑界面.md) |
| 信标数据的持有与合法性判定 | `BattleMap.can_place_beacon`（系统 03）+ 本系统的信标层做**交互** |
| 关卡数据的编辑 | [07 关卡编辑器](07-关卡编辑器.md) |
| 倍速的时间语义 | [01 时间与逻辑帧](01-时间与逻辑帧.md) |
| 地形与单位的美术呈现 | 系统 03 / 04 的渲染部分 + 美术 |
| 按钮的输入映射（ESC/R） | 现有 `game_scene.gd` 的 `_unhandled_input` |

### 2.3 边界上的接口约定

- 本系统**只调用**系统 06 的 `start()` / `reset()`，不自行改单位状态。
- 结算界面**只渲染** `ResultData`，不做任何算术（避免与系统 08 口径分叉）。
- 机制说明文档的**解析在表现层**，不进逻辑层（`src/core/` 不关心 Markdown）。

## 3. 数据结构

### 3.1 信标层状态

| 字段 | 说明 |
|---|---|
| `beacon_mode: bool` | 是否处于信标模式（工具条按钮切换） |
| `placements: Array[Vector2i]` | 已放置信标，**数组下标即序号**（第 1 个放的是信标 1） |
| `quota: int` | 来自关卡数据的 `beacon_quota` |
| `mode_label` | 序号显示风格：`123` / `ABC` / `I II III`（需求 3.2.3 提到三种；MVP 固定 `123`，见 8.2） |

`queued(available) = quota - placements.size()` —— 显示为「已用 n/N」。

### 3.2 机制说明文档格式

`res://data/help/机制说明.md`，按**二级标题**分节：

```markdown
# 机制说明

## 指令系统
指令由条件与行为组成……

## 指令的执行结构
从上向下执行……
```

| 解析支持 | 说明 |
|---|---|
| `##` 二级标题 | 分节标题，生成左侧节列表 |
| 段落 | 原样显示 |
| `-` 列表 | 原样显示为项目符号 |
| `**粗体**` | 加粗显示 |

> **只支持这四种**。不做完整 Markdown 渲染（表格、代码块、链接都不支持）——章节标题 + 段落 + 列表 + 粗体足够承载机制说明，复杂度可控。

### 3.3 结算数据来源

直接用系统 08 的 `ResultData`（[08](08-评价与结算.md) 3.2）。本系统不复制字段，直接持有引用。

## 4. 算法与交互

### 4.1 工具条状态同步

```
每帧（或状态变化时）：
    var st = level_session.current_state
    btn_start.disabled  = (st != BUILD)
    btn_reset.disabled  = (st == RESULT)
    speed_picker.disabled = (st == RESULT)
    beacon_button.visible = (st == BUILD)
    invalid_badge.visible = (st != RESULT and invalid_count > 0)
```

用 `EventBus` 的状态变化信号驱动（不每帧轮询），但 MVP 中每帧赋值的代价可忽略——**优先用信号**，避免后续引入高频轮询的习惯。

### 4.2 信标模式

| 操作 | 行为 |
|---|---|
| 点工具条「信标」按钮 | 进入/退出信标模式；进入时按钮高亮，鼠标变为信标光标 |
| 信标模式下点一个格子 | `can_place_beacon` 为真且 `queued > 0` → 追加到 `placements`；否则给出反馈（格子变红/提示「不可放置」或「信标已用完」） |
| 右键已放置的信标 | 撤回并从数组移除，**后续信标序号自动前移**（第 3 个撤了，原第 4 个变第 3 个） |
| 退出信标模式 | 恢复普通点选（点单位开指令面板） |
| 推演期 | 信标按钮不可见，信标不可改（需求 3.1） |

**撤回导致序号前移的连锁影响**：引用被撤回信标的指令会变成无效（系统 02 校验，[09](09-指令编辑界面.md) 4.5 标黄）。这是预期行为，不做自动修复——**自动改玩家的规则比失效更糟**。

### 4.3 关卡介绍

| 时机 | 行为 |
|---|---|
| 进入关卡（编制期开始） | 自动弹一次（FR-TUT-03 / 需求 12.1 决策） |
| 点工具条「关卡介绍」 | 随时重看 |
| 关闭 | 点关闭按钮 / `Esc` |

内容：`intro.title` + `intro.tips` 列表（来自关卡数据）；若 `tips` 为空则只显示标题与地图尺寸等基本信息。

### 4.4 结算界面

| 元素 | 内容 |
|---|---|
| 结果 | 「通关」 |
| 分项 | 指令复杂度 / 信标成本 / 时间成本（各带明细：条件数、行为数、信标数、用时） |
| 总分 | `total_score`，保留 1 位小数 |
| 最佳 | `best_score`，若 `is_new_record` 显示「新纪录！」 |
| 出口 | **重试**（回编制期，保留指令与信标）/ **下一关**（按 `manifest` 顺序；已是最后一关则禁用）/ **返回选关** |

失败时（`verdict == LOSE`）：只显示「失败」+ 失败原因（超时 / 全灭）+ **重试 / 返回选关**，无任何分数（FR-SCORE-06）。

### 4.5 暂停菜单改动

按需求 12.1 决策，**移除**「编辑指令」入口。保留：继续 / 重置关卡 / 返回主菜单。

> 现有 `scenes/ui/pause_menu.*` 已有「继续 / 设置 / 返回主菜单」结构，需要新增「重置关卡」并**确认没有**指令编辑入口。

### 4.6 敌人视野辅助显示

- 在敌方单位位置画一个半径 = `effective_vision_radius` 的圆（换算成像素）。
- 用 `_draw` 或一个 `CanvasItem` 子节点绘制，半透明描边，不做填充避免遮挡地形。
- 工具条或设置里给一个开关（FR-TUT-04「可开关的辅助显示」，默认开启）。
- **纯表现**：不参与任何判定（不遮挡视野、不影响条件求值）。

## 6. 验收

### 6.1 冒烟测试用例（数据与解析层）

| 用例 | 断言 |
|---|---|
| 工具条状态映射 | 三种会话状态下，六个按钮与倍速的 `disabled` 组合与 1.3 表完全一致 |
| 信标放置计数 | 放 2 个 → 显示「已用 2/4」；放满 4 个后再放 → 被拒 |
| 信标撤回序号前移 | 放 3 个后撤回第 2 个 → `placements` 长度为 2，且序号连续为 1、2 |
| 信标配额为 0 | `beacon_quota = 0` 时立刻拒绝放置并给提示 |
| 机制说明解析 | 给定样例 md → 解析出正确的节数与每节内容；粗体/列表被识别 |
| 机制说明文档缺失 | 文件不存在 → 面板显示「未找到机制说明」，不崩溃 |
| 选关列表 | 顺序 = `manifest.json` 的顺序；关卡名来自各自的 `name` |
| 结算渲染 | 给定 `ResultData` → 三个分项 + 总分 + 最佳全部就位，且数值与 `ResultData` 逐项相等（不重算） |
| 失败无分数 | `verdict == LOSE` → 界面不含任何分项与总分元素 |
| 暂停菜单无编辑入口 | 暂停菜单的按钮集合 == {继续, 重置关卡, 返回主菜单} |
| 视野圆半径 | 给定单位 → 绘制半径等于 `effective_vision_radius * TILE_PX` |

### 6.2 手动验收（人眼）

| 项 | 期望 |
|---|---|
| 工具条 | 六按钮从左到右一条排开；1920×1080 下不换行、不溢出 |

## 7. 风险与开放项

| 风险 | 说明 | 缓解 |
|---|---|---|
| 工具条挤压 | 六按钮 + 倍速 + 两个状态显示在 1920 宽下要排开 | 按钮用固定宽 + 图标（图标后置）；状态显示右对齐、可截断 |
| 信标序号前移的连锁 | 撤回中间信标会让后续指令全部失效 | 预期行为（4.2）；UI 上通过 [09](09-指令编辑界面.md) 的标黄即时暴露，不自动改玩家规则 |
| 机制说明解析范围 | 手写 Markdown 很容易用到不支持的语法 | 3.2 明确「只支持四种」；在文档顶部加一行注释说明限制 |
| 结算界面与系统 08 算术分叉 | 若 UI 再算一遍总分，可能与 `ResultData` 不一致 | 2.3 约定「只渲染不计算」；用例逐项比对 |
| 抽屉与工具条重叠 | 指令抽屉（1/3 宽）会盖住工具条左侧按钮 | 抽屉展开时把左侧三个信息按钮挡住的概率低（它们最左）；实测若冲突，抽屉展开时自动收起工具条左侧分组 |
| 暂停菜单的现有结构 | 现有暂停菜单有「设置」入口，需与新需求对齐 | 保留设置入口不影响；只需确认无指令编辑并**新增重置** |

**开放项（M6 打磨）**：

1. **图标化按钮**（现在用文字，需美术）。
2. **信标序号显示风格切换**（`123` / `ABC` / `I II III`）——需求 3.2.3 提到三种，**MVP 固定 `123`**（D 未定，属于纯表现，不阻塞）。
3. ~~结算界面的分数动画/评级~~ → **已确认不做评级**（D-16），只显示分数与历史最佳；分数动画属打磨项。
4. **单位血量条与减速图标**——需求未列，MVP 只显示在指令面板标题栏。
5. **美术资源替换**——**已确认本阶段全部使用纯色占位图形**（D-09），不做美术替换。
