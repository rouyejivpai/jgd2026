## 1. 目标产物

### 1.1 一句话

玩家点场上单位后弹出的**左侧 1/3 抽屉**：用「如果 / 则」两列 + 下拉列表，让玩家在不写任何文字的前提下编出一整套指令，并能拖拽调整优先级。

### 1.2 交付物清单

| 交付物 | 形式 | 说明 |
|---|---|---|
| 面板主体 | `ui/rule_panel/rule_panel.gd` | 抽屉容器：打开/关闭、单位标题、指令列表 |
| 指令行控件 | `ui/rule_panel/rule_row.gd` | 一行：序号、启用开关、条件列、行为列、删除按钮 |
| 条件/行为选择器 | `ui/rule_panel/atom_picker.gd` | 类型下拉 + 按 schema 动态生成的参数输入 |
| 拖拽排序 | `rule_row.gd` 内 | `_get_drag_data` / `_can_drop_data` / `_drop_data` |
| 参数控件工厂 | `ui/rule_panel/field_factory.gd` | 由参数 schema 生成 `SpinBox` / `OptionButton` / `CheckBox` |
| 自动化用例 | `tools/smoke_test.gd` 增量 | UI 交互不自动化，**但数据链路的每个操作都要有等价的数据层用例**（见 6.1） |

### 1.3 布局（对应策划案图 3，见 [`_refs/media/img003.png`](../../../_refs/media/img003.png)）

```
┌─ 指令面板（占屏宽 1/3，从左侧滑入） ───────────────────────┐
│ 单位：基础-攻击人工生命   HP 100/100     [×]              │
│ 条件逻辑： [ 与 ▾ ]   [+ 新增指令]                        │
├──────────────────────────────────────────────────────────┤
│ ⠿ 1  ☑ 如果 [视野内出现敌人 ▾] [半径 3.0]                │
│       则   [开火 ▾]                            [删除]     │
├──────────────────────────────────────────────────────────┤
│ ⠿ 2  ☑ 如果 [血量状态 ▾] [ < ▾] [60] %                   │
│       则   [沿着信标移动 ▾] [1 → 2 → 3]        [删除]     │
├──────────────────────────────────────────────────────────┤
│ ⠿ 3  ☑ 如果 [信号状态 ▾] [信号 1 ▾] [开 ▾]               │
│       则   [设置信号 ▾] [信号 2 ▾] [开 ▾]      [删除]     │
└──────────────────────────────────────────────────────────┘
```

- ⠿ = 拖拽把手；☑ = 启用开关（FR-CMD-09）；行首数字 = 优先级（数组下标 + 1）。
- 一行内「如果」列可放**多个**条件（同行竖排），「则」列可放**多个**行为。
- 无效指令整行标黄（见 4.4）。

## 2. 系统边界

### 2.1 本系统负责

- 抽屉的打开/关闭与当前编辑单位。
- 指令的增、删、启用/禁用、拖拽排序。
- 条件与行为的类型选择、参数录入（由 schema 动态生成控件）。
- 同类型行为互斥的 UI 约束（FR-CMD-03）。
- 条件逻辑「与 / 或」切换（每条指令一个）。
- 无效指令的标黄提示与总数角标（需求 12.1 决策）。

### 2.2 本系统明确不负责

| 不负责 | 归属 |
|---|---|
| 条件的**求值**、冲突覆盖、持续意图 | [02 规则引擎](02-规则引擎.md) |
| 枚举与参数 schema 的**定义** | 系统 02（本系统只消费） |
| 信标放置与撤回 | 信标层 + [10 主界面与HUD](10-主界面与HUD.md) |
| 单位的数值显示来源 | [04 单位与移动](04-单位与移动.md) |
| 倍速、开始、重置、关卡介绍按钮 | [10 主界面与HUD](10-主界面与HUD.md) |
| 关卡编辑器里的条件编辑面板 | [07 关卡编辑器](07-关卡编辑器.md)（**共用 schema，不共用控件**） |

### 2.3 边界上的接口约定

- 本系统**只改** `unit.rules`（`Rule` 对象列表），不求值、不缓存求值结果。
- 参数控件由**系统 02 提供的 schema** 生成；新增条件/行为类型时，只要在系统 02 补 schema，本系统无需改动（除非需要新的控件类型）。
- 编辑即时生效，**没有「保存指令」按钮**：编制期时间冻结，玩家看到的永远是当前规则表（推演期面板不可编辑，见 4.5）。

## 3. 数据结构

### 3.1 面板状态

| 字段 | 说明 |
|---|---|
| `target_unit` | 当前编辑的单位（`null` 表示未打开） |
| `is_open` | 抽屉展开状态 |
| `dragging_row` | 正在拖拽的行下标（`-1` 表示无） |
| `invalid_count` | 当前单位的无效指令数（供工具条角标） |

### 3.2 参数 schema（由系统 02 提供，本系统消费）

每个条件/行为类型声明自己的参数列表：

| 字段 | 取值 | 生成的控件 |
|---|---|---|
| `key` | 参数名 | — |
| `type` | `float` / `int` / `bool` / `enum` / `beacon_ref` / `signal_ref` / `beacon_seq` | 决定控件类型 |
| `min` / `max` / `step` | 数值范围 | `SpinBox` 的范围与步长 |
| `options` | 枚举项（值 + 显示名） | `OptionButton` 的项 |
| `default` | 默认值 | 新增该类型时的初值 |
| `label` | 显示名 | 控件前的文字 |

**关键**：`beacon_ref` / `signal_ref` / `beacon_seq` 三类参数的**候选项来自当前关卡数据**（信标数由玩家实际放置决定、信号数由 `signal_count` 决定）。因此下拉项需要**每次打开面板时重建**——玩家的信标是动态的。

### 3.3 条件逻辑的呈现

每条指令一行「条件逻辑：[与 ▾]」，作用于该行内的全部条件（需求 5.2 已确认不做嵌套）。默认「与」。

## 4. 算法与交互

### 4.1 打开/关闭

| 操作 | 行为 |
|---|---|
| 编制期点击场上单位 | 打开抽屉，`target_unit` 指向该单位，重建下拉候选项 |
| 点另一个单位 | 切换 `target_unit`，重建列表 |
| 点关闭按钮 / `Esc` | 关闭抽屉 |
| 双击地图空白 / 点已选中的单位 | 关闭抽屉（可切换的开关式） |
| 推演期 | **不打开**（需求 3.1：推演期不可暂停编辑指令） |

### 4.2 增删改

| 操作 | 数据改动 |
|---|---|
| 新增指令 | `rules.append(新建 Rule{enabled=true, logic=AND, conditions=[], actions=[默认开火]})` |
| 增删条件 | 该 `Rule.conditions` 追加/移除，参数取 schema 的 `default` |
| 增删行为 | 该 `Rule.actions` 追加/移除 |
| 切换启用 | `Rule.enabled` 取反 |
| 删除指令 | `rules.remove_at(i)` |
| 改参数 | 直接写回该 `Condition` / `Action` 的对应字段 |

> `actions` 为空时该指令等价于「什么都不做」，但**仍计入评价的条件/行为数量**（系统 08 口径）。UI 上给一个淡色提示「这条指令没有行为」。

### 4.3 拖拽排序

用 Godot 的 `Control` 拖拽接口：

| 回调 | 实现 |
|---|---|
| `_get_drag_data` | 返回 `{"row": i}` |
| `_can_drop_data` | 目标为同列表的行 |
| `_drop_data` | 在 `rules` 中把第 `i` 项移到目标位置，随后**刷新全部行号** |

排序即改数组顺序（需求 12.1 决策：数组下标即优先级）。

### 4.4 同类型行为互斥（FR-CMD-03）

新增行为时按**冲突键**（系统 02 的 `conflicts_with`）检查同行已有行为：

- 若冲突 → **不追加**，并把已有那项高亮闪烁 + 提示「同一条指令里不能同时开火与停火」。
- 若要换类型 → 替换而非追加。

### 4.5 无效指令标黄

`Rule.invalid_reason` 由系统 02 在求值/校验时写入（引用不存在的信标或信号）。

| 时机 | 行为 |
|---|---|
| 编制期信标变动（放置/撤回） | 本系统**主动重算**一次全部指令的 `invalid_reason`（不等到推演期） |
| 有无效指令 | 对应行底色标黄 + 悬停显示原因；工具条上显示总数角标（需求 12.1 决策：不弹窗、不阻断） |
| 推演期 | 保持标黄（玩家能看到「我这条废了」），但不可编辑 |

**重算实现**：调用系统 02 的 `validate_rule(rule, level_context)`，返回 `String`（空串表示合法）。这是纯函数，可以放心每 tick 调——但 MVP 只在「信标变动」与「打开面板」时调用。

### 4.6 抽屉的动画与遮挡

- 宽 = 屏幕宽度的 `1/3`（需求确认「左侧抽屉，占 1/3」）。
- 从左侧滑入（`Tween` 位移 + `modulate`），时长 `0.15s`。
- 展开时**覆盖**在地图之上（半透明背景板），不做挤压式布局避免地图重排。
- 顶部工具条用 `CanvasLayer` 层级高于抽屉？**否**——抽屉应盖住工具条左半部分（工具条按钮在右侧，实际不冲突）；工具条层级低一档即可。

| 条件与行为 | 条件列可放多个条件；「多条件折叠显示」进 MVP（D-20）：一行内条件多于 3 个时折叠为「3 个条件 ▸」，点开展开 |
| 复制到其它单位 | 右键指令行 → 「复制到…」→ 选择本关其它我方单位 → 追加到该单位规则表末尾（D-20） |

### 4.7 MVP 追加的两项便利功能（D-20）

| 功能 | 交互 | 数据改动 | 注意 |
|---|---|---|---|
| **指令复制到其它单位** | 行右键菜单 → 选目标单位（可多选）→ 追加 | 目标单位 `rules` 末尾追加该 `Rule` 的**深拷贝** | 必须是深拷贝，否则两个单位的指令会被联动修改；复制后需重算 `invalid_reason`（信标引用可能不同） |
| **多条件折叠显示** | 每行条件多于 3 个时自动折叠，点击展开 | 无（纯显示状态） | 折叠状态不写入数据；无效指令标黄在折叠状态下也要可见（行底色标黄，不依赖展开） |

## 6. 验收

### 6.1 数据层用例（可无头自动化）

UI 交互本身不自动化，但**每个 UI 操作对应的数据改动**都要有用例：

| 用例 | 断言 |
|---|---|
| 新增指令默认值 | `enabled == true`、`logic == AND`、`conditions` 为空 |
| 新增条件取默认参数 | 按 schema 的 `default` 赋值（如视野半径 = 0 表示取射程） |
| 同类型行为互斥 | 已有「开火」时追加「停火」→ 被拒；换类型 → 替换 |
| 删除指令 | 长度 -1，其余顺序不变 |
| 拖拽排序 | 把第 3 条移到第 1 位 → 数组顺序变化且行号连续 `1..n` |
| 启用开关 | `enabled` 取反后，系统 02 的求值结果随之变化（FR-CMD-09） |
| 条件逻辑切换 | `AND` ↔ `OR` 写回正确（FR-CMD-04） |
| 标黄逻辑 | 撤回一个被引用的信标 → 对应 `Rule.invalid_reason` 非空，`invalid_count` 增加（FR-CMD-08 相关） |
| 无行为提示 | `actions` 为空 → 该指令被标记（供 UI 显示提示） |
| 下拉候选项随信标变化 | 放 2 个信标 → `beacon_ref` 候选为 2 项；撤回 1 个 → 变为 1 项 |
| 指令复制是深拷贝 | 复制一条指令到单位 B → 改 B 的该条参数，单位 A 的指令**不受影响**（D-20） |
| 复制后重算无效标记 | 目标单位的信标引用无效时，复制过去的指令 `invalid_reason` 非空（D-20） |
| 折叠不改数据 | 折叠/展开多条件行 → `Rule.conditions` 长度与内容不变，仅显示状态变化 |

### 6.2 手动验收（人眼）

| 项 | 期望 |
|---|---|
| 布局 | 抽屉占 1/3 宽；行内「如果/则」两列对齐；与策划案图 3 的观感一致 |
| 拖拽手感 | 拖拽时有插入位置指示线；放下后立即生效 |
| 参数控件 | 数值用 `SpinBox`（可键入）、枚举用 `OptionButton`、开关用 `CheckBox`，无需手写文本（FR-CMD-10） |
| 标黄可见 | 无效行在滚动中也能一眼看到 |
| 遮挡 | 展开时不遮挡右侧地图上的单位（保证「一边看位置一边写规则」） |

## 7. 风险与开放项

| 风险 | 说明 | 缓解 |
|---|---|---|
| 下拉候选项的动态性 | 信标由玩家动态放置，下拉项必须每次重建 | 3.2 明确：打开面板与信标变动时重建候选项 |
| 拖拽排序与滚动冲突 | 长指令列表下拖拽容易误触滚动 | 把拖拽把手限定在行首 ⠿ 图标上，其余区域不启动拖拽 |
| 参数 schema 演化 | 新增参数类型时控件工厂要支持 | 6.1 的「参数控件」走通用工厂；新增类型时只加一个分支，并补一条用例 |
| 无效指令的重算时机 | 若只在打开面板时重算，工具条角标在面板关闭时不会更新 | 4.5 明确：信标变动时也重算（由信标层发 `EventBus.beacon_changed` 触发） |
| 抽屉遮住地图 | 占 1/3 宽后，左侧地图被挡 | 抽屉半透明 + 只在编制期展开；玩家可随时关闭。若实测影响大，改为「抽屉展开时地图自动向右平移」 |
| 与编辑器的控件重复 | 条件参数控件在两处都用 | schema 共用（3.2）、控件工厂**各自实现**（编辑器面板字段更多、含胜负条件参数）；接受少量重复，换取两处独立演化 |

**开放项**：

1. ~~是否需要「指令复制粘贴」~~ → **已确认进 MVP**（D-20，见 4.7）。
2. ~~是否需要条件/行为的折叠成一行显示~~ → **已确认进 MVP**（D-20，见 4.7）。
3. **是否需要按单位分组的面板**（左侧列出全部单位，点选切换）？当前靠点场上单位切换；若实测不便，加一个单位列表。**仍开放，M6 再定**。
4. **是否需要指令模板/预设规则集**？MVP 不做。
