## 1. 目标产物

### 1.1 一句话

把「开火意图」变成**有飞行时间的实体子弹**，用碰撞体完成命中，结算伤害与状态，并在单位死亡时触发清理。

### 1.2 交付物清单

| 交付物 | 形式 | 说明 |
|---|---|---|
| `Weapon` | `combat/weapon.gd` | 冷却递减、目标选择、生成子弹 |
| `Projectile` | `combat/projectile.gd` | `Area2D`：直线飞行、射程耗尽、命中判定 |
| `Damage` | `combat/damage.gd` | 伤害应用、状态（减速）附加、死亡触发 |
| 子弹视觉占位 | `Projectile` 子节点 | 小方块/圆点（美术后置） |
| 自动化用例 | `tools/smoke_test.gd` 增量 | 见 6.1 |

### 1.3 两条契约

1. **单位自己不开火、不选目标**：`Weapon` 每 tick 询问单位 `wants_to_fire()`，然后由**本系统**选择一个最近敌人并生成子弹（需求 D3 / FR-CBT-08）。
2. **子弹只有飞行时间，没有预判**：朝「开火瞬间目标所在位置」的方向直线飞（需求 12.2 决策）。

## 2. 系统边界

### 2.1 本系统负责

- 每个单位的开火冷却计时与递减。
- 开火时的目标选择（**调用** `BattleState.query_nearest_enemy`，不自己遍历单位）。
- 子弹的生成、参数（速度、射程、伤害、命中半径、命中附带状态）。
- 子弹直线推进、射程耗尽销毁、撞墙销毁。
- 命中判定与解算（伤害、减速层数、死亡触发）。
- 子弹的注册与注销（供 `BattleState` 清理与调试显示）。

### 2.2 本系统明确不负责

| 不负责 | 归属 |
|---|---|
| 「开不开火」的决策 | [02 规则引擎](02-规则引擎.md) → 单位的 `fire_mode` |
| 单位数值（伤害、射程、攻速、弹药速度）的定义 | [11 数据配置](11-数据配置.md) |
| 减速状态与血量的**存储**、移动速度的换算 | [04 单位与移动](04-单位与移动.md) |
| 「谁是最近敌人」的实现 | [03 网格地图](03-网格地图.md) 的 `BattleState` |
| 墙体的碰撞体生成 | [03 网格地图](03-网格地图.md) |
| 死亡后的胜负判定 | [06 关卡数据与胜负条件](06-关卡数据与胜负条件.md) |
| 命中特效、屏幕震动、命中停顿 | [10 主界面与HUD](10-主界面与HUD.md) + `Game.hitstop()`（打磨阶段） |

### 2.3 边界上的接口约定

- 本系统**只通过** `BattleState` 查询单位，不直接遍历场景树。
- 伤害写入走 `Health`（系统 04）的方法，不直接改 `hp` 字段。
- 子弹**不参与**「子弹互相碰撞」（需求 12.2 决策）。

## 3. 碰撞分层（本轮定稿）

需求文档给的分层是「单位 1 / 障碍 2 / 我方子弹 3 / 敌方子弹 4 / Hurtbox 5」。为**不写阵营判断代码**，Hurtbox 按阵营拆成两层：

| 层 | 用途 | 掩码 |
|---|---|---|
| `1` | 单位本体 | `2`（仅障碍） |
| `2` | 障碍 | — |
| `3` | 我方子弹 | `2`（障碍） + `6`（敌方 Hurtbox） |
| `4` | 敌方子弹 | `2`（障碍） + `5`（我方 Hurtbox） |
| `5` | 我方 Hurtbox | `0`（不主动探测） |
| `6` | 敌方 Hurtbox | `0`（不主动探测） |

由此**免费得到**四条需求保证：

| 保证 | 由什么保证 |
|---|---|
| 子弹不伤害友方（FR-CBT-02） | 我方子弹掩码不含层 5；子弹不会因撞到友军而消失 |
| 敌人子弹不伤害敌人 | 敌方子弹掩码不含层 6 |
| 子弹被墙挡住并销毁（需求 6.1） | 掩码含层 2 |
| 子弹互不碰撞 | 任何子弹的掩码都不含层 3 / 4 |

## 4. 算法

### 4.1 开火（tick 顺序的第 5 步）

```
for unit in BattleState.units_sorted_by_id():          # 升序，确定性
    if not unit.wants_to_fire():  continue
    unit.cooldown_remaining = max(0.0, unit.cooldown_remaining - TICK_DELTA)
    if unit.cooldown_remaining > 0.0:  continue
    target = BattleState.query_nearest_enemy(unit, unit.effective_range)   # 射程内最近
    if target == null:  continue                        # 没有合法目标就不开火
    spawn_projectile(unit, target)
    unit.cooldown_remaining = unit.stats.attack_interval
```

要点：

| 点 | 说明 |
|---|---|
| 冷却**只在想开火时**递减 | 停火期间冷却保持不变，重新开火时不需要「等冷却转完」；这是最符合直觉的口径。**已确认保持此口径** |
| 目标必须在**射程内** | 视野半径与射程在 MVP 中默认相等；若关卡覆盖使二者不同，开火仍以 `effective_range` 为准 |
| 无目标则不开火 | 不消耗冷却 |
| 遍历顺序按 id 升序 | FR-TEST-08 的确定性要求 |

### 4.2 生成子弹

```
spawn_projectile(shooter, target):
    dir = (target.position_logic - shooter.position_logic).normalized()
    p = Projectile.new()
    p.position_logic = shooter.position_logic          # 从单位中心出发
    p.direction      = dir
    p.speed          = shooter.stats.projectile_speed  # 默认 12 距离/秒
    p.remaining_range= shooter.effective_range         # 飞满射程即销毁（需求 12.2 决策）
    p.damage         = shooter.stats.damage
    p.radius         = shooter.stats.projectile_radius # 默认 0.3
    p.on_hit_status  = shooter.stats.on_hit_status     # "" 或 "slowed"
    p.team           = shooter.team                    # 决定碰撞层 3 或 4
    BattleState.register_projectile(p)
```

**不预判**：`dir` 用的是开火瞬间目标的位置，不做提前量（需求 12.2 决策）。目标移动会导致打空——这是可接受的，且便于玩家归因。

**发射点不偏移**：从单位中心出发。因为单位与子弹的碰撞层不重叠（单位是层 1，子弹掩码不含 1），不会自伤或自我销毁。

### 4.3 推进与销毁（tick 顺序的第 6 步）

```
for p in BattleState.projectiles:
    step = p.speed * TICK_DELTA
    p.traveled += step
    if p.traveled >= p.remaining_range:
        p.destroy(); continue                           # 飞满射程即销毁
    p.position_logic += p.direction * step
```

销毁条件三者任一：**飞满射程** / **撞障碍** / **命中目标**（需求 6.6）。

### 4.4 命中解算

由 `Area2D` 的 `area_entered` 触发：

```
on_area_entered(area):
    if p.consumed:  return                              # 防同一 tick 多次命中
    if area belongs to same team:  return                # 保险（掩码已排除，双保险）
    p.consumed = true
    var victim = area.get_unit()
    Damage.apply(p, victim)
    p.destroy()
```

```
Damage.apply(p, victim):
    if victim.is_dead:  return                          # 已死则丢弃（见 4.5）
    victim.health.take_damage(p.damage)
    if p.on_hit_status == "slowed":
        victim.health.set_slowed()                      # 单一开关，不叠加（D-06）
    if victim.health.hp <= 0.0:
        victim.die()                                    # 标记死亡 + 从 BattleState 注销
```

**撞墙**：子弹的 `Area2D` 不检测 `StaticBody2D`（Area 检测的是 Area）。因此障碍用 `body_entered` 单独处理，或者给子弹再加一个 `body_entered` 连接：

```
on_body_entered(body):
    if body.collision_layer has 2 (障碍):  p.destroy()
```

> 实现提示：`Area2D` 的 `area_entered` 收 `Area2D`，`body_entered` 收 `PhysicsBody2D`。两个信号都要接；掩码里同时含层 2 与目标 Hurtbox 层即可。

### 4.5 子弹与「本 tick 刚死」的单位

若同一 tick 内两个子弹命中同一单位，第一发致死并注销后，第二发的 `area_entered` 仍可能已排队。因此 `Damage.apply` 必须先判 `victim.is_dead`，已死则直接丢弃这次伤害（不重复计伤、不重复触发死亡）。

## 5. 接口

### 5.1 从系统 04 读取

`wants_to_fire()`、`effective_range`、`position_logic`、`team`、`stats`（`damage` / `attack_interval` / `projectile_speed` / `projectile_radius` / `on_hit_status`）、`cooldown_remaining`（可写）。

### 5.2 从系统 03 读取

`query_nearest_enemy(unit, radius)`、`register_projectile` / `unregister_projectile`、`units_sorted_by_id()`。

### 5.3 向系统 04 写入

`health.take_damage()`、`health.add_slow_stack()`、`unit.die()`。

### 5.4 向系统 10 / 08 输出

- `EventBus.unit_died`（由 `die()` 发出，供 UI 与胜负检查用）。
- 调试显示需要时暴露 `projectiles` 列表。

## 6. 验收

### 6.1 冒烟测试用例

| 用例 | 构造 | 断言 |
|---|---|---|
| 冷却节奏 | 攻速 1 发/秒（`attack_interval = 1.0`），持续开火 600 tick | 生成约 10 发子弹（容差 ±1） |
| 停火不消耗冷却 | 开火 1 发后停火 5 秒，再开火 | 再开火时冷却已就绪（不需要等） |
| 射程内才开火 | 敌人在射程外 | 不生成子弹 |
| 自动选最近 | 射程内两个敌人（一近一远） | 子弹飞向近者；等距时飞向 id 更小者（FR-CBT-03） |
| 不预判 | 目标在子弹飞行途中横移 | 子弹沿原方向飞，不会拐弯追（需求 12.2） |
| 射程耗尽销毁 | 无遮挡、目标在射程外但视野内 | 子弹在 `traveled >= range` 处销毁，不再前进 |
| 撞墙销毁 | 墙在射手与目标之间 | 子弹撞墙即销毁，目标血量不变 |
| 命中造成伤害 | 伤害 10 的子弹命中 100 血单位 | 血量变 90 |
| 击杀清理 | 血量 10 的单位被伤害 10 的子弹命中 | `is_dead == true`，从 `BattleState` 移除，尸体仍在场景树 |
| 友军免伤 | 我方子弹与我方单位重叠 | 子弹**穿过**（不销毁、不造成伤害） |
| 敌我分明 | 敌方子弹穿过其他敌人 | 不造成伤害 |
| 子弹互不碰撞 | 两发对向子弹轨迹重叠 | 两者都继续飞行，互不销毁 |
| 减速附加 | 冰寒单位命中敌人 | 目标 `slow_stacks` 从 0 变 1 |
| 重复命中不计 | 同一 tick 两发子弹命中同一目标 | 只结算一次伤害（第二发丢弃） |

### 6.2 对应需求验收

| 需求编号 | 覆盖方式 |
|---|---|
| FR-CBT-01 | 射程 10 的子弹飞行需要多个 tick（`12 距离/秒` 下约 50 tick） |
| FR-CBT-02 | 友军免伤 / 敌我分明 |
| FR-CBT-03 / FR-TEST-08 | 自动选最近 + 等距取 id 小者 |
| FR-CBT-04 | 冷却节奏 |
| FR-CBT-05 | 减速附加（数值口径见 [04](04-单位与移动.md) 4.5） |
| FR-CBT-06 | 击杀清理 + 触发 `unit_died` |
| 需求 6.1 第 3 条 / 6.6 | 射程耗尽销毁 / 撞墙销毁 |
| 需求 12.2 决策 | 不预判、子弹互不碰撞 |

## 7. 风险与开放项

| 风险 | 说明 | 缓解 |
|---|---|---|
| 高速子弹穿透 | 速度 12 距离/秒在 60 tick 下每 tick 走 0.2 格，远小于单位 0.8 格尺寸 → **不会穿透** | 若将来把子弹速度调到 `> 48 距离/秒`（每 tick > 0.8 格），需要改成射线检测；用例覆盖「命中造成伤害」可及时暴露 |
| `Area2D` 与 `StaticBody2D` 混用 | 容易只接了 `area_entered` 而漏掉撞墙 | 4.4 已明确两个信号都要接；用例「撞墙销毁」守护 |
| 同一 tick 多命中 | 已死单位仍可能收到第二次伤害 | `Damage.apply` 先判 `is_dead`（4.5） |
| 冷却口径歧义 | 「停火时冷却是否继续转」有两种合理口径 | 已确认「只在想开火时递减」（4.1）；若实测手感不对改一行即可 |
| 目标在射程外但视野内 | MVP 中视野=射程，正常情况下不会出现；但关卡可覆盖使二者不同 | 开火一律以 `effective_range` 为准（4.1），视野只影响条件求值 |

**已关闭的待确认项**：

- ~~子弹飞行途中目标死亡时如何处理~~ → 已确认**子弹继续沿原方向飞，可能命中后面的敌人**（D-07）。子弹因此完全无状态、不记忆目标，与「不预判、不做自主决策」的取向一致。代价是偶尔出现「一发打死两个」的伤害溢出，接受。
- ~~子弹之间是否碰撞~~ → 已确认**不碰撞**（D-08）。
- ~~减速是叠加层数还是单一状态~~ → 已确认**不叠加、固定 50%、无持续时间**（D-06），因此 `Damage.apply` 调用的接口是 `health.set_slowed()` 而不是 `add_slow_stack()`。
