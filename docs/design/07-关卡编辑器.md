## 1. 目标产物

### 1.1 一句话

一个**运行时**的关卡编辑器：在游戏进程里刷地形、放单位、配胜负条件、写文案，存成 JSON 后一键试玩——让「设计一关」不需要碰代码，也不需要重启 Godot。

### 1.2 交付物清单

| 交付物 | 形式 | 说明 |
|---|---|---|
| 编辑器场景 | `editor/editor_scene.tscn/.gd` | 独立场景，从主菜单进入；运行时 F1 可开关 |
| 地图视图 | `editor/tools/map_view.gd` | 中央区域：地形绘制、网格、单位与信标标记、缩放平移 |
| 工具集 | `editor/tools/*.gd` | 瓦片刷、单位放置、目标区刷、擦除 |
| 左侧工具栏 | `editor/panels/toolbar.gd` | 工具切换、尺寸设置、保存/载入/试玩按钮 |
| 右侧属性面板 | `editor/panels/inspector.gd` | 按选中对象动态生成字段（单位/格子/关卡/胜负条件） |
| 条件编辑器 | `editor/panels/condition_editor.gd` | 增删胜利/失败条件、选类型、填参数、切组间逻辑 |
| 关卡读写 | `editor/level_io.gd` | JSON 存读、`manifest.json` 维护、只读回退 |
| 撤销栈 | `editor/undo_stack.gd` | 快照式，深度 50 |
| 自动化用例 | `tools/smoke_test.gd` 增量 | 见 6.1（编辑器的**数据层**可无头测试） |

### 1.3 布局

```
┌──────────────────────────────────────────────────────────────┐
│ 左侧工具栏        │        中央地图视图        │  右侧属性面板   │
│ · 工具切换        │   · 网格与地形绘制         │  随选中对象切换  │
│   刷空地/墙/目标区 │   · 我方/敌方单位标记      │  · 单位条目      │
│   放单位/擦除      │   · 信标序号标记           │  · 格子信息      │
│ · 地图尺寸         │   · 缩放/平移              │  · 关卡全局      │
│ · 单位类型选择     │                            │  · 胜负条件      │
│ · 保存/载入/试玩   │                            │  · intro 文案    │
└──────────────────────────────────────────────────────────────┘
```

**UI 用代码构建 Control 节点**（概设 D7），不用 `.tscn` 手摆：属性面板要按数据动态生成，代码构建比两处维护更省。

## 2. 系统边界

### 2.1 本系统负责

- **地形编辑**：刷空地 / 障碍 / 目标区域，改地图尺寸（含扩缩容时的数据保留策略）。
- **单位编辑**：放置、删除、改类型、改阵营、改坐标、配 `overrides`、配 `is_primary_target`。
- **信标与信号**：配备额 `beacon_quota`、信号数 `signal_count`；可选预置信标（MVP 不做，见 8.2）。
- **胜负条件编辑**：增删 `win` / `lose` 条件、选类型、填参数、切组间逻辑（`any` / `all`）。**这是编辑器的一部分**（需求 9.3）。
- **关卡全局**：`id`、`name`、`order`、`time_limit`、`intro.title` / `intro.tips`。
- **存盘与载入**：写 `res://data/levels/*.json`，维护 `manifest.json`。
- **一键试玩**：保存后直接切到玩法场景进入编制期。
- **撤销/重做**：快照式，深度 50（Ctrl+Z / Ctrl+Y）。

### 2.2 本系统明确不负责

| 不负责 | 归属 |
|---|---|
| 关卡数据的**运行时语义**（怎么装配、怎么判胜负） | [06 关卡数据与胜负条件](06-关卡数据与胜负条件.md) |
| 关卡校验规则的**定义** | 系统 06 的 `validate()`；编辑器**调用**它 |
| 地形美术、瓦片贴图 | [10 主界面与HUD](10-主界面与HUD.md) + 美术 |
| 单位的规则（指令）编辑 | [09 指令编辑界面](09-指令编辑界面.md)（编辑器只放单位，不配规则） |
| 评价系数的编辑 | 需求 9.2 提到「关卡可覆盖评价系数」，MVP 不做（见 8.2） |
| 游玩流程、胜负判定 | 系统 06 + [10](10-主界面与HUD.md) |

### 2.3 边界上的接口约定

- 编辑器**只操作 `LevelData`**（系统 06 的运行时数据类），不直接碰 `BattleMap` / `BattleState`。
- 保存前**必须**调用系统 06 的 `LevelData.validate()`，保证编辑器存出的文件一定能被运行时载入（校验口径唯一）。
- 编辑器**不改变** `manifest.json` 的既有顺序，除非用户显式调整（见 4.4）。

| 键 | 内容 |
|---|---|
| **指令复制到其它单位**（D-20） | 在编辑器里选中一个我方单位 → 可把它的整张规则表（或单条指令）复制到本关其它我方单位，避免「三个单位各写一遍」。深拷贝语义，与 [09](09-指令编辑界面.md) 4.7 同一实现 |

> 关卡编辑器**只负责搬运规则表**，不提供指令内容编辑（那是系统 09 的事）。编辑器里的复制入口面向「关卡作者预设一批单位模板」的场景。

## 3. 数据结构

### 3.1 编辑器会话状态

| 字段 | 说明 |
|---|---|
| `level_data` | 正在编辑的 `LevelData` |
| `source_path` | 来源文件路径（`res://data/levels/xxx.json` 或「未保存的新关卡」） |
| `active_tool` | 当前工具枚举：`PAINT_EMPTY` / `PAINT_WALL` / `PAINT_GOAL` / `PLACE_UNIT` / `ERASE` / `SELECT` |
| `selected_unit_type` | 放置单位用的类型 id |
| `selected_team` | 放置单位的阵营 |
| `selection` | 当前选中的对象（格子 / 单位 / 关卡全局 / 某个条件） |
| `dirty` | 有未保存改动（用于退出确认与标题栏 `*`） |

### 3.2 撤销栈

快照式：每次「会改变 `level_data` 的操作」完成后，把 `level_data.to_json_string()` 压栈。

| 项 | 值 |
|---|---|
| 深度 | 50（需求 12.1 决策） |
| 粒度 | 一次鼠标拖拽刷多格算**一次**操作（鼠标按下到抬起为一个事务） |
| 排除 | 纯选中变化、缩放平移**不入栈** |
| 重做 | 另存一条前进栈；执行新操作时清空前进栈 |

## 4. 算法

### 4.1 编辑操作 → 数据改动

| 操作 | 数据改动 | 校验 |
|---|---|---|
| 刷瓦片 | `map.tiles[j][i] = id` | 若该格上有单位且新瓦片不可通行 → 拒绝并提示 |
| 擦除（右键/擦除工具） | 若该格有单位则删单位，否则置为 `0` | — |
| 放置单位 | `units` 追加 `{team, type, pos:[i,j], overrides:{}}` | 该格已有单位则拒绝；瓦片不可通行则拒绝 |
| 删除单位 | 从 `units` 移除 | — |
| 改地图尺寸 | 重建 `tiles`，**保留**与新区重叠区域的数据；越界单位与原目标区一并清理 | 缩小时若会丢弃单位 → 确认提示 |
| 改 `beacon_quota` / `signal_count` | 直接改 | 值必须 ≥ 0 |
| 增删胜负条件 | `win.conditions` / `lose.conditions` 追加或移除 | 参数按类型必填 |
| 切组间逻辑 | `win.logic` / `lose.logic` | 只能是 `any` / `all` |

**目标区域与 `reach_position` 的联动**：编辑器把「刷成目标区域（瓦片 2）的格子集合」自动同步进 `win` 里 `reach_position` 条件的 `area` 参数。这样关卡作者只需刷格子，不用手填坐标。

> 实现注意：只同步**由编辑器自动维护的那个** `reach_position` 条件（标记 `auto_area: true`）；手写的其它条件不动。

### 4.2 保存流程

```
保存():
    1. level_data.id 非空、且与文件名一致（不一致则提示并同步）
    2. level_data.validate() 失败 → 弹出错误列表，不写盘
    3. 写 res://data/levels/<id>.json（回退策略见 4.4）
    4. 若 id 不在 manifest.levels 中 → 追加到末尾（新关卡默认排在最后）
    5. 写回 manifest.json
    6. dirty = false；提示「已保存到 <路径>」
```

### 4.3 试玩流程

```
试玩():
    1. 有未保存改动 → 先保存（试玩必须跑在真实文件上，避免「试玩的和存盘的不一致」）
    2. 把「本关 id」写入一个运行时会话变量（不用改 manifest）
    3. SceneLoader.goto("res://scenes/game/game_scene.tscn")
    4. 玩法场景载入该 id 的关卡数据，进入编制期
```

### 4.4 写盘回退策略（重要）

`res://` 在**导出后的构建里是只读的**（打包进 pck）。因此：

| 环境 | 行为 |
|---|---|
| 编辑器/调试运行（未导出） | 直接写 `res://data/levels/`，方便在 Godot 编辑器里看到文件变化 |
| 写入失败（只读） | 回退写 `user://levels/`，并提示实际路径；载入时**先查 `user://levels/` 再查 `res://data/levels/`**，同名以 `user://` 优先 |

这样「在自己机器上编辑」与「玩别人打包的版本」都能正常工作，且玩家自制关卡有落盘位置。

## 6. 验收

### 6.1 冒烟测试用例

编辑器的 UI 不可无头测试，但**数据层与读写层可以**，这部分必须自动化：

| 用例 | 断言 |
|---|---|
| 新建关卡默认值 | `signal_count == 3`、`beacon_quota == 4`、`map 7×7` 全空地、`win` 含一个 `reach_position` |
| 刷瓦片改数据 | 刷 5 个墙 → `tiles` 中恰好 5 个 `1` |
| 目标区联动 | 刷 3 个目标区 → `win` 中 `auto_area` 条件的 `area` 恰好 3 格 |
| 放/删单位 | 放 3 个敌人 → `units` 长度 +3；删除后复原 |
| 非法放置被拒 | 往墙上放单位、往已有单位的格再放 → 拒绝且数据不变 |
| 改尺寸保留数据 | 7×7 → 9×9，原内容在新网格的对应位置不变 |
| 改尺寸缩小丢单位 | 触发确认标志（返回「需要确认」而不是静默丢弃） |
| 撤销/重做 | 连续 3 次操作后 Ctrl+Z 三次 → 数据等于初始；Ctrl+Y 三次 → 回到最终态 |
| 撤销深度 | 执行 60 次操作 → 栈长度不超过 50，最早的状态被丢弃 |
| 保存→重载一致 | `to_json` → 写文件 → `from_json` → 两份数据逐字段相等（**FR-TEST-05 的核心**） |
| 保存前校验 | 构造一个非法 `LevelData`（单位在墙上）→ 保存被拒，文件未被改写 |
| manifest 维护 | 新 id 保存后出现在 `manifest.levels` 末尾；已存在的 id 不重复追加、顺序不变 |
| 写盘回退 | 模拟 `res://` 写入失败 → 落到 `user://levels/`，且载入时优先读到它 |

## 7. 风险与开放项

| 风险 | 说明 | 缓解 |
|---|---|---|
| UI 代码构建量大 | 属性面板要按数据类型动态生成，容易写成一坨 | 把「字段描述」抽成数据（字段名/类型/范围/默认值），面板只做通用渲染；条件参数也走同一套 schema |
| 编辑器与运行时校验分叉 | 编辑器放过了运行时载入不了的数据 | 保存前调用**同一个** `validate()`（2.3 约定） |
| 缩地图丢数据 | 玩家改尺寸后单位被悄悄删掉 | 4.1 要求返回「需要确认」，不静默丢弃 |
| `res://` 只读 | 导出后无法保存 | 4.4 回退 `user://levels/` + 载入优先级 |
| 目标区与 `area` 双写不同步 | 手改了 `area` 又刷了格子 | 只同步带 `auto_area: true` 的条件；手写条件不动（4.1） |
| 编辑器与 09 的控件重复 | 条件/行为下拉在编辑器与指令面板都要用 | 条件/行为 schema 由系统 02 提供，两处共用同一份枚举与 schema（见 [09](09-指令编辑界面.md) 3.2） |

**开放项（MVP 不做，已确认）**：

1. **关卡级评价系数覆盖**（需求 9.2 提到）——`extra` 字段留位，编辑器不提供 UI。
2. **预置信标**（需求 9.2 提到「是否允许预置信标」）——MVP 只做「玩家在编制期放」。
3. **网格吸附之外的任意形状**（手工摆碰撞体）——已确认按瓦片生成碰撞体。
4. **关卡复制/另存为**——M6 打磨阶段再加。
