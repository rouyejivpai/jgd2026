## R0 UI 清单与设计规范（先做，1 份文档）

输出 `docs/UI_INVENTORY.md`：
1. 逐界面列出全部元素、状态数、设计尺寸（画布 1920×1080）：主界面；设置浮窗；章节地图（地图、节点三态 ×5 区域、Boss 节点、名牌、详情面板、进入 / 回放按钮）；局内顶栏与右上角功能组（1×/2×、暂停、设置、退出、任务、机制说明）；任务弹窗、机制说明弹窗；底栏（开始、角色卡、清空、提示 / 推荐阵型、预算）；侧栏角色详情（头像、六项属性、特性）与指令编辑（行为 / 条件一 / 条件二 / 与或 / 添加 / 删除 / 为何不成立）；结算面板；提示面板；部署反馈（不可放置提示框、脚下血条三色、地格高亮两种、信标数字牌）。
2. 风格基准：沿用 04 §1.1 色板（骨白、灰紫、干血红、炼金金）、Noto Serif SC / Cinzel 字体；暗调低饱和；UI 不得出现文字以外的水印、Logo。
3. 公共件规范：面板九宫格（切片边距）、按钮四态、下拉、滑条、开关；全部放 `assets/ui/common/`。
4. 切片命名与 `manifest.json` 写法以 10 §1.2 为准；补充本方的约定（如切片 2× 导出规则）写进本文档。
5. **总规则文件对齐**：`tasks/资源生产任务包_GPT.md` 的路径与 §0 环境表已由架构方按本机改好，§0.1 记录了实际工具链。资源方负责两件事：(a) 给 `tools/cutout.py` 加 `--native-alpha` 选项（跳过品红键与 rembg，只做裁边 / 缩放 / 居中 / 底边留白），并把该文件 §2、§3 中涉及品红背景的说明改成原生透明流程；(b) `art_manifest.json` 中含 "magenta" 的 prompt 改为透明背景措辞（`id`、`kind`、输出目录不动）。改动记入 `ASSET_REPORT_P3.md`。

## R4 场景大地图 ×8（10 §7）

每关：
- `assets/backdrops/level_0X_full.png`（完整画面，障碍与地物画进去，1920×1080）；
- `assets/backdrops/level_0X_base.png`（同一画面去掉可分离障碍，只剩地面与远景）；
- `assets/backdrops/obstacles/level_0X/<n>.png` 透明切片 + `obstacles.json`（每块：`file`、占据的格 `cells`、`anchor_px`、`size_px`），格坐标用 `python tools/print_playfield_rects.py --png` 的标线图对齐，`cells` 必须落在该关 `blocked` 格内（见 `data/levels/level_0X.json`）。
- 做法按录屏：先给 GPT 整体需求生成完整画面，再分离 / 移除指定元素得到 base 与切片。
- 玩法矩形内仍须平坦可叠网格（07 §1 规则不变），障碍块是贴地的矮物件（骨堆、碎板、血池、荆棘根、矮墙段），不得高出一格高度遮住后排单位。
- 自检脚本：切片在 base 上回贴应与 full 像素一致（差异 < 1%），结果写报告。

## R6 艺术字动效素材（10 §1.5；追加任务，2026-10-05）

- **R6a 主界面标题（先做，可与整图审阅批次并行）**：标题艺术字的动效视觉由本会话**自主设计**。交付 `assets/ui/main_menu/art_text/title/`：分层素材（`base.png` 底字、`glow.png` 发光 / 自发光遮罩、`ember.png` 火星 / 粒子遮罩等，按设计需要）或帧序列（`frames/0001.png…` + fps，可用 `tools/gen_burning_text.py` 作起点），加 `motion.md`（时长、循环方式、节奏、各图层叠加顺序与混合模式）；manifest 以 `kind: "art_text"` 登记，静止态（t = 0 或帧 0）必须与 `design.png` 一致。
- 按钮动效由程序方自主设计，默认不需新素材；程序方若经 QUESTIONS 索取额外图层（高光扫过遮罩、描边发光等），按同目录 `slices/` 补交。
- **R6b 其余艺术字**：主界面经用户目视通过后，按决策 ⑭ 清单（章节标题、关卡名牌、结算「胜利 / 失败」、战斗开始提示）逐个交付，格式同 R6a，可随 R2 / R3 切片一起或单独提交。
- 不做：UI 正文、按钮文字、属性数字等普通文字。
