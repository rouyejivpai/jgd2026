## 第二轮已修复（2026-10-18）

- **开放优先级**：「生命最低 / 首个入视野 / 生命上限最高」改为玩家可选（commands.json 去掉 player:false），仍按解锁链和关卡 allowed 显示。实测：c07 菜单出现「生命上限最高」，c10 出现「生命最低」，c16 出现「首个入视野」。
- **过期提示**：c12、c18、c25 改为与当前推荐解一致；c19 改为玩家手搭可赢的做法（模拟实测：一个信标，加「射程内敌人 → 停止」，攻击选「生命上限最高」，11.7 秒胜）。
- **开发者文字**：22 关 hints 第 3 条去掉了坐标和秒数，改用部署区、缺口、墙角等地标描述；c09 路线名改为中路 / 上路 / 下路；织骨者说明去掉 `**`。
- **名字和数量**：c25 的 B1–B3 命名为工头·一 / 二 / 三；c29 改为「带两个人就买不起信标」；c04 改为「两条巡道贴着上下两边」；c07 的优先级名称改成与界面一致。

## 仍待处理

### 1.（已完成）「追击」可选目标；c05 改为两条指令的教法
- 「追击」行和「攻击」一样带目标与对象下拉，默认「最近」（rule_row.gd、strings 的 action_text.chase 改为「追击{target}（不攻击）」）。
- c05 的推荐阵型改为玩家能手搭的版本（rules_format: dual）：两名基础形态，都是「始终 → 攻击·最远」加「始终 → 追击·最远」，实测 8.4 秒胜。引导新增「追过去」「追最远的」两步，第一步改为放两个基础攻击形态，不再高亮快速形态卡。
- 更正：之前说 c05 手搭打不过，是因为测试时只把追击挂在「可见敌人」下（守卫在视野外，追击不会触发）。改成「始终 → 追击」后，即使追击保持「最近」也能 9.2 秒胜。单人，或基础 + 快速形态，仍然会输。

### 2. 敌人面板显示的是通用说明（代码问题）
每关 `initial_units[].public_rule_text` 都没有被读取，敌人面板显示的是 units.json 里的通用文字（例如 c05 的祭司、c15 的守卫）。注意：这些逐关文字里还有坐标（如 c04 的「y=1」），接入之前要一起改写。

### 3. 小的用词问题
c06 标题「祭司行列」，但本关没有祭司；c17、c27 的副标题描述的元素本关没有；c21 有一处语病；「雷」「骨浆」「花粉」三种叫法混用。
