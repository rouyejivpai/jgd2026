## Q-001 Cinzel 字体在 google/fonts 中只有可变字体
- 现象：04 §2.8 要求 `Cinzel-Regular.ttf` / `Cinzel-Bold.ttf`，但 https://github.com/google/fonts/tree/main/ofl/cinzel 目前只有 `Cinzel[wght].ttf`（可变字体）。
- 相关文档：04 §2.8

- 需要架构方决定：无（如希望直接用可变字体 + FontVariation，可改）。

## Q-012 文档未细化、由实施方按最贴近原文解释的算法细节
- first_seen 锁定"有效"含 filter 匹配（01 §6.5）：若锁定目标不符合当前这条规则的 filter，则视为本条锁定失效并按本条 filter 重新取 seen_order 最小者写入锁定。现有数据中同一单位的 first_seen 规则 filter 一致，不受影响。
- 无锁定时 first_seen 先按 seen_order 取首个并写入锁定，再应用 `enemy_in_range`（即锁定的是"首个入视野者"，而不是"射程内首个入视野者"）。
- retreat 决胜"离当前格更近"按 BFS 步数计；不含当前格；严格大于当前位置得分才算改进。
- chase 目标格"距目标 ≤ range-0.15 的最近可行走格"：BFS 步数最少 → 距目标近 → 格索引小。
- 普通攻击（第 8 步）与延迟爆炸放置（第 9 步）的距离/落点使用第 7 步移动后的当前位置；决策（第 6 步）与移动目标只读快照。
- 规则未写 target 时，`enemy_visible` / `enemy_in_range` 等条件按"最近、任意"口径取候选。
- `COOLDOWN` 原因码在"攻击类指令已成立、目标在射程内、冷却未好"时设置，供状态图标使用。
- 需要架构方决定：如与设计意图不符请指出，均有单元测试可随之调整。

## Q-085 R4 障碍块清单的坐标约定与对齐底图（P7）
- 10 §7 只给了 `anchor_px` / `size_px` 字段名，没写坐标基准。程序侧采用（`GroundLayer.obstacle_rects()` 与 `tools/obstacle_check.py` 同一公式）：
  - 坐标都是**整图像素**（1920×1080 的 full / base 上量）；
  - `anchor_px` = 块左上**相对所占格外接框左上**的偏移（可为负，块可以比格子大、向上探出）；`size_px` = 块在整图上的尺寸；
  - 所占格外接框左上 = 玩法矩形左上 + (最小列 × cell_px, (高 − 1 − 最大行) × cell_px)，玩法矩形与 cell_px 以 `python tools/print_playfield_rects.py` 为准。
  - 资源侧从 full 里按像素框切块时，用 `python tools/obstacle_check.py anchor <关> <x> <y> <列,行>…` 直接得到 anchor_px；交付前 `python tools/obstacle_check.py check` 做回贴自检（差异 < 1%）。
- **对齐底图**：有 `scene.obstacles` 的关卡，backdrop 视为按标线图画的对齐底图，按设计坐标 1:1 居中铺（与玩法矩形同一换算），不再按第二阶段的「视口宽 + 2×横移余量」放大约 1.54 倍（Q-067）。副作用：镜头横移（10 §6.4）时两侧会露出底色；P6 详情改为居中弹窗后横移已基本不会触发（Q-082）。
