## 1. 技术选型

| 项目 | 决定 | 理由 |
|---|---|---|
| 引擎 | Godot **4.7.2 stable**（本机 `H:\Godot_v4.7.2\Godot_v4.7.2-stable_win64_console.exe`；2026-10-04 自 4.6.2 升级） | 已安装；4.x API |
| 语言 | **GDScript**，全程静态类型（`var x: int`、函数返回类型必写） | 执行方熟悉度最高、无编译链 |
| 维度 | 2D，俯视 3/4 视角 | 网格策略游戏 |
| 渲染器 | **Forward Plus**，开启 `rendering/viewport/hdr_2d = true`（2D 发光需要） | PC 平台 |
| 分辨率 | 设计分辩率 1920×1080，`stretch/mode = canvas_items`，`stretch/aspect = expand` | 全屏可缩放 |
| 格子尺寸 | `TILE_SIZE = 96` 像素 | 13×9 地图 = 1248×864，留出 UI 面板空间 |
| 坐标系 | 模拟层用策划坐标：**x 向右、y 向上、左下为 (0,0)**，格中心 = (x+0.5, y+0.5)。表现层转换：`screen = Vector2((x+0.5)*TILE, (height-1-y+0.5)*TILE)` | 与关卡册一致，避免转写错误 |
| 数据格式 | 所有定义（单位、特性、关卡、提示、对白）为 **JSON**（`res://data/`），存档为 JSON（`user://save.json`） | AI 手写 `.tres` 极易出错；JSON 可校验 |
| 测试 | **GUT**（`addons/gut`），headless 运行 | 模拟核心必须有自动化测试 |
| 版本控制 | git，`.gitignore` 排除 `.godot/` | — |
| 物理引擎 | **不使用**。模拟全部为自写定步长逻辑，Node2D 仅做表现 | 确定性与倍速一致性要求 |

**铁律**
1. `scripts/sim/*` 与 `scripts/data/*` 中**禁止** `extends Node`、禁止 `get_node`、禁止访问 `Engine.get_frames_per_second()`、禁止 `randf()`（只能用 `SimWorld.rng`）。
2. 表现层**禁止**修改模拟数据（生命、位置、冷却）。只读快照，只发命令。
3. 一个关卡的所有数值来自 JSON，脚本中不出现关卡专属数字。
4. 所有玩家可见文字来自 `data/strings.json` 或关卡 JSON，脚本中不写死中文（调试文字除外）。

## 5. 数据层

### 5.1 数据类（`scripts/data/`，`extends RefCounted`）

每个类提供 `static func from_dict(d: Dictionary, ctx: String) -> <Class>`，遇到缺失必填字段、未知枚举、越界坐标时 `push_error("[%s] ..." % ctx)` 并把 `DataRegistry.has_errors` 置 true。**不得静默填默认值掩盖错误**（可选字段除外，可选字段的默认值写在 §02 数据规格文档）。

| 类 | 关键字段 |
|---|---|
| `UnitDefinition` | id, display_name, kind(unit/structure), faction_default, max_hp, attack, attack_speed, move_speed, vision, range, traits: Array[String], allowed_actions, default_rules: Array[RuleDef], visuals{sprite, portrait, projectile, scale, light_color}, description, public_rule_text |
| `TraitDefinition` | id, type(delayed_blast), params: Dictionary, public_text |
| `RuleDef` | enabled, condition_mode(all/any), conditions: Array[ConditionDef], target: TargetDef, action: ActionDef |
| `ConditionDef` | type, params(ratio/distance/op) |
| `TargetDef` | selector(nearest/farthest/lowest_hp/first_seen), filter(any/unit/structure) |
| `ActionDef` | type(idle/attack/chase_attack/chase/retreat/follow_route), params(route_id, loop, threat_radius, search_depth) |
| `LevelDefinition` | id, index, title, biome, background, grid{width,height,blocked}, deploy_zone{cells}, slots: Array[SlotDef], initial_units: Array[SpawnDef], routes: Dictionary, allowed{conditions,selectors,actions}, objectives{win,lose}, seed, briefing, hints, fail_feedback, recommended_deploy, rewards, verification |
| `SlotDef` | id, unit_id, fixed(bool), editable_rules(bool), default_pos(可选) |

## 6. 模拟核心（`scripts/sim/`）

### 6.1 时间模型

- 固定步长 `SIM_DT = 1.0 / 30.0`（30 步/秒）【策划建议值】。
- `project.godot`：`physics/common/physics_ticks_per_second = 30`。`BattleController._physics_process()` 每 tick 调用 `world.step()` **speed 次**（1 倍 1 次，2 倍 2 次）。暂停时 0 次。
- 模拟时间 `SimClock.time` 仅在 `step()` 内累加 `SIM_DT`。任务计时（如第七关 20 秒）只看 `SimClock.time`，与真实时间、帧率无关。
- 表现层位置插值：`UnitView` 保存 `prev_pos` 与 `cur_pos`（每次 step 后更新），`_process()` 中用 `Engine.get_physics_interpolation_fraction()` 插值。
- 随机：`SimWorld.rng = RandomNumberGenerator.new(); rng.seed = level.seed`。第一章八关**不使用任何随机**，`rng` 仅为接口预留。

### 6.2 SimWorld.step() 顺序【策划已定 11.3】

```
1. clock.time += SIM_DT
2. BlastSystem.tick(): 递减每个爆炸的剩余时间；到期的爆炸进入 detonate_list
3. 对 detonate_list：对半径内、与施放者敌对的存活单位结算伤害 → 加入 damage_queue；发出 blast_detonated 事件
4. 对所有存活单位：cooldown = max(0, cooldown - SIM_DT)
5. snapshot = 本步开始时所有单位 (pos, hp, alive, faction) 的只读副本
6. 对每个存活单位（按 unit id 升序）：
     decision = RuleEvaluator.evaluate(unit, snapshot, world)   # 只读 snapshot
     unit.apply_decision(decision)                              # 记录当前规则下标、目标、原因码；规则变化发事件
7. 对每个存活单位：Movement.apply(unit, decision, SIM_DT)       # 更新 pos（基于 snapshot 的目标位置）
8. 对每个存活单位：Combat.try_attack(unit, decision) → 若可攻击，把 {source, target, damage} 推入 damage_queue，cooldown = 1/attack_speed，发出 attack_fired 事件
9. TraitSystem.tick(): delayed_blast 特性冷却完毕且存在合法目标 → 放置爆炸（记录目标当时位置），发出 blast_placed 事件
10. 批量结算 damage_queue：hp -= damage（同步结算，允许互杀）；hp<=0 → alive=false，发出 unit_died 事件；清除所有以其为目标的锁定
11. 更新"进入视野顺序"记录（见 6.5）
12. ObjectiveSystem.evaluate(): 先判失败再判胜利；若已决出 → world.result 置位，发出 battle_ended 事件，后续 step() 直接返回
13. events 列表交给 BattleController 消费并清空
```

### 6.3 SimGrid

- `width, height, walkable: PackedByteArray`（索引 `y*width+x`）。
- 内置 `AStarGrid2D`：`diagonal_mode = DIAGONAL_MODE_NEVER`（四方向），`default_compute_heuristic = HEURISTIC_MANHATTAN`。障碍格 `set_point_solid`。
- `cell_center(c: Vector2i) -> Vector2` = `(c.x+0.5, c.y+0.5)`；`pos_to_cell(p) = Vector2i(floor(p.x), floor(p.y))`。
- `find_path(from: Vector2i, to: Vector2i) -> Array[Vector2i]`；不可达返回空数组。
- `reachable_within(from, depth) -> Array[Vector2i]` BFS（撤离用）。
- **基础不做单位实体堵路**【策划已定】：单位之间可重叠，仅障碍格不可走。

### 6.4 SimUnit 运行数据

```
id: int                   # 场内唯一，己方从 1 起、敌方从 101 起、建筑从 201 起（稳定、用于决胜）
def: UnitDefinition
faction: int              # SimTypes.Faction
pos: Vector2              # 连续坐标（格单位）

```

### 6.5 目标候选与选敌【策划已定 4.2/4.4，细节为建议】

**候选集**：对立阵营、存活、`filter` 匹配（any/unit/structure）、且 `dist(center, center) <= vision`（圆形感知，无视线遮挡【策划已定】）。

**进入视野序号**：每步结束时，对每个单位遍历对立单位：若本步可见且之前不在 `seen_order` 中 → 记录 `seen_order[other] = world.seen_counter++`；若本步不可见 → 从 `seen_order` 移除。首帧（开战瞬间）所有已可见者按 `unit id` 升序赋序号【策划已定：稳定规则并在说明中展示】。

**排序与决胜**：
| selector | 主排序 | 决胜 1 | 决胜 2 |
|---|---|---|---|
| nearest | 距离升序 | seen_order 升序 | unit id 升序 |
| farthest | 距离降序 | 同上 | 同上 |
| lowest_hp | 当前生命**数值**升序 | 同上 | 同上 |
| first_seen | 若 `lock_target` 有效（存活、可见、敌对）→ 直接返回它；否则取 seen_order 最小者并写入 `lock_target` | — | unit id |

浮点距离比较用 `is_equal_approx` 视为同距。

**first_seen 与射程条件的配合（重要）**：当 selector 为 `first_seen` 且 `lock_target` 仍有效（存活、可见、敌对、filter 匹配）时，候选集被替换为**仅含锁定目标**，之后再应用 `enemy_in_range` 等条件。因此"[射程内有敌人 → 攻击首个入视野者]、[可见敌人 → 追击首个入视野者]"两条规则的效果是：锁定目标在射程内就打它，不在射程内就追它，**绝不因为别的敌人更近或在射程内而改打别人**。只有锁定失效（死亡/离开视野）才会重新选取。

**锁定清除**：目标死亡、离开视野、被移除 → `lock_target = -1`，下一次决策按规则重新选取（可能重新锁定其他人，也可能规则不成立进入下一条）。普通 nearest/farthest 每次决策重新选。

### 6.6 RuleEvaluator.evaluate()【策划已定 4.1/4.4/11.4】

```
for i, rule in unit.rules:
    if not rule.enabled: continue
    ctx = { candidates: 按 rule.target 得到的排序候选, chosen: 候选[0] 或 -1 }
    results = [check(cond, unit, ctx) for cond in rule.conditions]
    ok = all(results) if mode == ALL else any(results)   # 空条件列表 = 无条件成立
    if not ok:
        unit.rule_fail_reasons[i] = 首个失败条件的原因码     # 供 UI 展开"为何不成立"
        continue
    return Decision(rule_index=i, target=ctx.chosen, action=rule.action, reason=OK)
return Decision(rule_index=-1, target=-1, action=IDLE, reason=NO_RULE_MATCHED)
```

条件语义：
| type | 成立条件 | 失败原因码 |
|---|---|---|
| `always` | 永真 | — |
| `self_hp_below` {ratio} | `hp / max_hp < ratio` | COND_HP_NOT_BELOW |
| `enemy_visible` | 候选集非空 | COND_NO_VISIBLE_ENEMY |
| `enemy_in_range` | 候选集中存在 `dist <= range` 者；**选敌只在这些射程内者中进行**（"存在可攻击目标应把射程加入条件"） | COND_NO_ENEMY_IN_RANGE |
| `target_distance` {op: "<" / ">", value} | `chosen` 存在且 `dist(chosen) op value` | COND_DISTANCE_FAIL / NO_TARGET_CANDIDATE |
| `retreat_possible` {threat_radius, search_depth} | 存在 BFS 可达格使"到最近威胁的距离"比当前增加 ≥ 0.5 | COND_NO_ESCAPE |

**成立但暂时无法执行**（如 `attack` 但目标不在射程）：不回退到下一条规则，单位原地等待，`reason = TARGET_OUT_OF_RANGE` 并显示【策划已定 4.4】。

### 6.7 行为语义（Movement / Combat）

| action | 移动 | 攻击 | 完成/阻塞 |
|---|---|---|---|
| `idle` | 不动 | 不攻击 | — |
| `attack` | 不动 | 目标在射程内且 cooldown==0 → 结算 | 目标出射程 → 等待 TARGET_OUT_OF_RANGE |
| `chase_attack` | 若目标不在射程：寻路到"距目标 ≤ range-0.15 的最近可行走格"，沿路以 move_speed 前进 | 在射程内时攻击（不再移动） | 不可达 → PATH_BLOCKED，原地等待 |
| `chase` | 同上 | **不攻击** | 同上 |
| `retreat` {threat_radius=默认 vision, search_depth=3} | 威胁 = threat_radius 内可见敌人。在 BFS `search_depth` 步内的可达格中选"到最近威胁距离最大"者，决胜：离当前格更近 → 格索引小。朝其格中心移动 | 不攻击 | 无改进格 → FLEE_NO_DIRECTION 原地等待 |
| `follow_route` {route_id, loop=false} | 按路点序列前进（路点之间用寻路），到达终点：loop 则回到第一个，否则 ROUTE_FINISHED 原地 | 不攻击 | 路点不可达 → PATH_BLOCKED |

- **移动实现**：每步 `pos = pos.move_toward(next_waypoint_center, move_speed * SIM_DT)`；到达当前路点（距离 < 0.05）取下一个。路径每 `PATH_REFRESH_STEPS = 6` 步或目标格变化时重算。
- **普通攻击**【策划已定 5.1】：结算时检查目标存活且 `dist <= range`；伤害 = attack（无防御/命中/闪避）；结算后发事件，表现层播放弹道，**生命变化不等待弹道**。`attack_speed == 0` 的单位永不攻击。切换规则**不重置冷却**。
- **射程/视野距离**用中心点欧氏距离；寻路步数与之无关。

### 6.8 特性（TraitSystem）

当前 Demo 只有一个真正的特性类型，其他"特性"均用规则列表表达（数据驱动，面板照样公开）。

**`delayed_blast`** 参数：`damage, radius, delay, cooldown, selector(默认 farthest), filter(默认 unit), range(放置最大距离，默认 = vision)`
流程【策划已定 5.4】：冷却为 0 且存在可见合法候选（按 selector 排序取首个，且距离 ≤ range）→ 创建 `Blast{pos=目标当时位置, radius, damage, remaining=delay, source_faction}` → 发 `blast_placed` 事件 → 冷却 = cooldown。到期对半径内敌对存活单位结算伤害。**目标死亡不取消已放置爆炸；落点不随目标移动。**

**多威胁撤离**（第四关猎犬）= 规则 `[retreat_possible → retreat]`，`retreat` 的最大最小距离算法天然综合全部威胁，方向抵消时由决胜规则稳定裁决【对应策划 5.3 建议】。

### 6.9 ObjectiveSystem

每步在伤害与死亡之后评估；**失败优先于胜利**【策划已定 6.3】。

| type | 判定 | 用途 |
|---|---|---|
| `annihilate` | 所有 `counts_for_annihilate && faction==enemy` 的单位死亡 | 胜利 |
| `destroy` {targets: [spawn_id]} | 列出的单位全部死亡 | 胜利 |
| `survive` {target: spawn_id, seconds} | `clock.time >= seconds` 且目标存活 | 胜利（第七关） |
| `unit_dead` {target} | 目标死亡 | 失败 |
| `all_allies_dead` | 所有 `faction==ally && kind==unit` 死亡（建筑不计） | 失败 |
| `reach_zone` {target, cells} | 目标所在格 ∈ cells | 失败（第六关祭司逃离） |

`ObjectiveSystem` 还输出 UI 所需进度：剩余秒数、目标剩余生命、"威胁已清除"标志（敌人全灭但计时未到）。

### 6.10 SimEvent（Dictionary，`type` 为 `SimTypes.EventType`）

`attack_fired{source,target,damage}`, `damage_applied{target,amount,source,hp_after}`, `unit_died{unit,killer}`, `blast_placed{blast_id,pos,radius,remaining,source}`, `blast_detonated{blast_id,hits:Array}`, `rule_changed{unit,rule_index,reason}`, `target_changed{unit,target}`, `objective_progress{...}`, `battle_ended{result,reason}`。每个事件含 `time`。

### 6.11 重置与快照【策划已定 3.2/11.4】

- `BattleController.reset()`：**丢弃**旧 `SimWorld`，从 `LevelDefinition` 重新构建新世界，再把玩家的部署与规则配置重新注入并校验。不逐项恢复。
- 玩家配置保存结构（也是存档结构）：`{ slot_id: { pos: [x,y], rules: [RuleDef...] } }`。
- 校验（`DeploymentValidator`）在"开始"前执行，问题列表通过 `validation_failed` 发出：
  - 槽位未部署 / 位置不在部署区 / 两单位同格 / 位置在障碍或禁放格
  - 规则引用了未解锁或本关禁止的条件/选敌/行为
  - 同条规则冲突（当前只有一个行为，天然无冲突；留接口）
  - 空规则列表允许（单位将待机），但给出警告

## 7. BattleController（`scripts/battle/battle_controller.gd`）

阶段机 `SimTypes.Phase`: `DEPLOY → RUNNING ⇄ PAUSED → ENDED`。

| 命令 | 允许阶段 | 行为 |
|---|---|---|
| `place_unit(slot_id, cell)` / `remove_unit(slot_id)` | DEPLOY | 修改部署，发 `deployment_changed` |
| `set_rules(slot_id, rules)` | DEPLOY | 修改并发 `rules_changed` |
| `start()` | DEPLOY | 校验 → 构建 SimWorld → RUNNING；锁定编辑 |
| `pause()/resume()` | RUNNING/PAUSED | 暂停中不可编辑【策划已定】 |
| `set_speed(1 or 2)` | 任意 | 只影响每 tick 步数 |
| `reset()` | 任意 | 回到 DEPLOY，保留配置（§6.11） |
| `exit()` | 任意 | 保存配置到存档 → 返回选关 |

`_physics_process`: 若 RUNNING，循环 `speed` 次 `world.step()`，每次把 `world.events` 转发到 `EventBus.sim_event` 并交给表现层队列；若 `world.result != NONE` → ENDED，弹结算。

**确定性验收**：同一配置 1 倍与 2 倍必须得到相同结果。实现 `world.state_hash()`（拼接所有单位 pos/hp 四舍五入到 1e-4 后 `hash()`），测试中对比。

**UnitView**（`scenes/battle/unit_view.tscn`）
- 棋盘精灵为 **Q 版**（256×256 画布内约 200px 高），`Body.scale = 0.5 * def.visuals.scale`，显示约 100px 高；立绘与头像另见 04 文档 §2.2–2.3。
- `Shadow(Sprite2D)` → `Body(Sprite2D, material=unit_material)` → `FactionBase(Sprite2D)`（己方：骨白圆环底座；敌方：暗红荆棘底座——阵营不只靠颜色区分【策划已定】） → `HpBar(自绘)` → `StateIcon`（待机原因图标）→ `SelectionRing`。
- 代码驱动动画（无逐帧序列）：
  - 待机：`breathing.gdshader` 轻微缩放 + 顶点蠕动（血肉感）
  - 移动：按移动方向轻微倾斜 + 底座波纹
  - 攻击：Tween 前冲 0.08s 回弹 0.15s；同时 FXLayer 生成弹道（0.12–0.25s 飞行，仅表现）
  - 受击：`hit_flash` 白闪 0.08s + 位移抖动 2px
  - 死亡：`dissolve.gdshader` 1.0s 溶解 + 骨灰粒子，之后 `queue_free`
- 位置插值见 §6.1。

**BlastMarker**：地面红环（`blast_marker.gdshader`）显示半径，环内填充随倒计时收缩，上方倒计时数字（Cinzel 字体）；到期闪光 + 冲击波粒子 + PointLight2D 脉冲。

**TargetLines**：运行中显示每个单位→当前目标的细线（己方骨白、敌方暗红、30% alpha）；可在设置中关闭；第二关首次失败后强制高亮两秒【关卡册 3.2】。

**后期**：`UI` 之下的 `PostFX (CanvasLayer)`：全屏 `ColorRect` 用 `post_vignette_grain.gdshader`（暗角 + 胶片噪点 + 轻微色差）；WorldEnvironment glow（强度 0.6，阈值 1.1）。
