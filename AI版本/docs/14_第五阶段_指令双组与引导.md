## 1. 指令模型：两组独立求值

### 1.1 分组
- **攻击组**：攻击（`attack`，带目标选择）、停火（`hold_fire`）。
- **移动组**：沿信标移动（`follow_beacons`）、追击（`chase`）、撤离（`retreat`）、停止（`idle`）、等待（`wait`），以及只给敌人的沿路线（`follow_route`）。
- `chase_attack`（追击并攻击）只留给旧数据，两组都算（`SimTypes.action_in_group`），不进玩家菜单。

数据格式不变，仍是一个 `rules` 数组。每条指令属于哪组由行为类型决定；数组内的相对顺序就是组内优先级。

### 1.2 求值（`RuleEvaluator.evaluate`）
- `SimUnit.dual_rules = true`（玩家单位）：移动组、攻击组各自从上往下取第一条成立的指令，结果合成一个决策 `SimDecision`：主字段是移动部分，`attack_*` 是攻击部分。`Movement` 读移动部分，`Combat` 读攻击部分，所以单位可以边走边打。
- 组内仍沿用原规则：「成立但不可执行则等待，不回退」，`wait` 按边沿触发。
- **攻击组选目标**：按目标选择排序后，取第一个在射程内的候选；射程内没有时，取排序第一的可见候选（本步移动后进入射程即可开火）。条件（如目标距离）的候选口径与旧口径相同。没有任何候选时，原因码为 `NO_TARGET_IN_RANGE`；停火时为 `HOLDING_FIRE`。
- **敌人和关卡预置单位**仍按旧单列表口径（`dual_rules = false`），行为与第四阶段完全一致。第四阶段的 `override` 字段只对旧口径生效。

### 1.3 新目标选择（`TargetSelector`）
| id | 名称 | 口径 |
|---|---|---|
| `highest_hp` | HP最高 | 当前生命最高 |
| `most_damage` | 造成伤害最高 | 累计造成伤害（`SimUnit.damage_dealt`，结算伤害时累加）最高；同值取最近 |
| `first_in_range` | 第一个进入射程 | 按 `SimUnit.range_order`（射程内且可见时编号，离开即移除）取最早者 |

旧的 `lowest_hp`、`first_seen`、`highest_max_hp` 保留给敌人和旧数据，在 `commands.json` 里标 `player: false`，不进玩家菜单。

### 1.4 旧数据折算（`RuleDef.migrate_legacy`）
旧单列表先按旧求值顺序排好（覆盖指令在前），再逐条展开，组内相对顺序不变：
- 攻击 → 攻击 + 同条件同目标的「停止」（旧口径攻击时原地不动）
- 追击并攻击 → 追击 + 攻击
- 移动类 → 原样 + 同条件同目标的「停火」（旧口径移动时不开火）
- 等待 → 原样（不加停火。等待结束后旧口径会继续向下，停火镜像跟不上，见 Q-089）

折算的地方：关卡推荐指令（`rules_format` 缺省为 `legacy`，加载时折算；按双组编写的关卡写 `"rules_format": "dual"`）、Boss 第二阶段推荐、存档 v4→v5、试玩场景（`playtest_scenarios.json`，同样支持 `rules_format`）。

**等价验证**：八关 25 个试玩场景按「旧单列表 → 折算 → 双组求值」运行，`run_playtests -- --check` 与第四阶段基线逐场景完全一致（结果、用时、阵亡、state_hash）。另有单元测试逐步比对 300 步。

### 1.5 数据与解锁
- `commands.json`
  - 行为加 `group` 字段。
  - `group_limits`：攻击 5、移动 5（暂定）。
  - `new_unit_rules`：新单位预填两条，攻击组「始终 → 攻击·最近」、移动组「始终 → 沿信标移动」。
  - 选敌支持 `player: false`。
  - 菜单顺序：攻击、停火、沿信标移动、追击、撤离、停止、等待。
- **通用指令**：停止、停火与信标、等待一样，不受关卡 `allowed`、解锁和形态限制（`DeploymentValidator.action_gated`）。
- **兼容旧数据**：关卡或形态的 `allowed` 里有 `chase_attack` 时，视为同时允许追击和攻击（`ActionDef.expand_allowed`）；已解锁 `chase_attack` 也视为已解锁这两者（`DeploymentValidator.action_unlocked`）。
- **新校验**：
  - `RULES_OVER_LIMIT`：某组超出条数上限，只提醒、不阻止开始。
  - `BEACONS_EMPTY`：改为只提醒。新单位预填了沿信标，没放信标时原地不动。
- **存档 v5**：
  - 玩家指令折算为双组。
  - 已解锁 `chase_attack` 时补解锁「追击」「攻击」和追击的解锁键。
  - 补齐新版初始解锁。
  - 新增 `tutorials_seen`。
- **初始解锁（测试内容）**：追加 追击、停火、三种新目标选择。

## 2. 指令编辑界面（暂用版式）
- 详情侧栏的指令区分「攻击策略（n/5）」「移动策略（n/5）」两段，攻击在上。每段有标题、条数、一行说明、指令行，以及「＋ 攻击指令 / ＋ 移动指令」。超出侧栏时沿用侧栏原有的滚动。
- 每组满 5 条后，该组添加按钮禁用，行为列表中该组的行为也禁用。
- 「优先级 N」按组内序号编号；拖拽只能在组内排序；行为下拉只列同组行为。
- 条件一为空时显示「始终」。
- 追击行不显示目标选择，改为固定文字「最近的敌人」，数据里的目标固定为 最近 / 任意。
- 玩家行不再显示「覆盖」勾选（组内优先级就是覆盖）。敌人的只读面板仍是单列表。
- 移动组的停火、攻击组的停止等折算出的指令，在界面上就是普通指令，可以删除或调整。

## 3. 统一强制引导

### 3.1 数据（`data/teaching.json`，由配置器编辑）
```
levels.<关卡 id>:
  test: true                      开发期测试内容（标题前加「【测试】」）
  tutorial.steps: [ 步骤… ]
  allowed / rewards / hints / mechanic_hint   可选，覆盖关卡 JSON 的同名字段（allowed、rewards 按键覆盖）
style: 遮罩颜色、高亮金边、留白、箭头、说明框宽度等表现参数
```
**步骤字段**（详见 `scripts/data/teaching_def.gd`）：

| 字段 | 取值 |
|---|---|
| `title` | 标题 |
| `text` | 说明文字 |
| `targets[]` | 高亮目标，每项一个 `kind`：`ui`（HUD 节点名，或「名字/子路径」）、`cell`、`cells`、`deploy_zone`、`unit`（预置单位 spawn id）、`ally`（第一名已部署己方）、`none` |
| `advance` | `next`（下一步按钮）、`click`（点高亮处）、`event` |
| `event` | `deployed`、`ally_selected`、`enemy_selected`、`beacon_placed`、`beacon_mode`、`rules_changed`、`battle_started` |
| `block` | 是否只放行高亮处。默认：有高亮且推进方式不是 `next` 时为 true |
| `arrow` | 箭头方向 |
| `panel` | 说明框位置 |
| `phase` | `deploy` 或 `running` |
| `after` | 战斗进行到第几秒才出现 |

第七关数据冻结：只能配置引导，不能覆盖其他字段（GDScript 与 Python 两边的校验都会拦）。

### 3.2 运行（`TutorialDirector` + `TutorialOverlay`）
- **呈现**：遮罩、高亮挖空、金边，箭头指向第一个目标，说明框按位置偏好避开高亮，显示步骤计数和「跳过引导」。
- **点击限制**：`block` 时只有高亮处能点（`_has_point`），可以把单位从卡牌拖进部署区。
- **推进**：按下一步、点击高亮处，或等 EventBus 事件。
- **阶段**：开战后，部署阶段的步骤作废；战斗中的步骤到点出现，并暂停战斗。
- **让路**：剧情、设置、结算出现时，引导暂时隐藏。
- **只出现一次**：每关只自动出现一次，完成或跳过都记入存档 `tutorials_seen`。
- **配置器预览**：不写存档，显示「返回配置器」。
- **拾取模式**：点界面元素，得到最近的有固定名字的祖先节点；点地图，得到地块。结果带回配置器。
- **常用界面元素名**：`StartButton`、`Card_<形态>`、`SidePanel`、`BeaconModeButton`、`Group_attack`、`Group_move`、`HintButton`、`MechanicsButton`。

### 3.3 测试内容（`test: true`）

## 4. 配置器（`tools/config_editor.tscn`，开发工具，不进导出包）
- **打开方式**：主菜单按 F10，或命令行 `Godot --path . -- --config-editor`。
- **左侧**：关卡列表，按现有编号，标注 引导 / 覆盖 / 测试。
- **引导步骤页**：
  - 步骤增删、复制、上下移。
  - 编辑文字、推进方式、事件、点击限制、箭头、说明框、阶段、秒数。
  - 目标增删、排序；「拾取目标」进入该关点选。
  - 「预览本关引导」带着未保存的步骤进入该关。往返时未保存的编辑会保留。
- **解锁表页**：
  - 勾选本关可用的 行为 / 条件 / 目标选择，以及通关解锁（行为、条件、目标、形态、解锁键）。
  - 「恢复本关原值」。
  - 下方是全部关卡总览；「导出解锁表」写 `docs/15_指令解锁表.md`（也可运行 `tools/export_unlock_table.gd`）。
- **提示文案页**：机制提示、四层提示，可以用关卡原文或自定义。
- **保存**：先校验（越界地块、未知事件、第七关覆盖等会被指出，有问题时不保存），再写 `teaching.json` 并重新加载全部数据。

## 5. 异常状态粒子
- 参数在 `data/status_fx.json`。`StatusParticles` 生成 CPUParticles2D，用运行时生成的柔边圆点，不需要美术资源。
- `status_overlay.sync_particles` 按「单位 × 状态」创建发射器并跟随单位；状态结束或单位死亡后停止发射，粒子放完再回收。头顶圆牌保持原样。
- 设计：
  - 易伤：红色碎片从身上迸出后下落。
  - 麻痹：短促跳动的黄白电火花，绕身一圈。
  - 减速：脚边缓慢下沉的蓝色微粒。
- `energy` 是亮度倍数（大于 1 时能透过战斗场景的整体压暗，并带一点辉光）。UI 动效总闸关闭时不发射。
- 截图：`take_screenshots --levels=level_c05 --phase=deploy --demo=status_fx --select=none`。

## 7. 待确认（汇总见 QUESTIONS Q-089～Q-093）
1. 攻击组的「默认行为」理解为预填「始终 → 攻击·最近」；「始终」显示为条件一的默认项。
2. 「HP最高」按当前生命，「造成伤害最高」按该敌人累计造成的伤害。

5. 现有关卡的提示文案、机制提示里仍有旧口径的说法（例如 c03「把攻击放在沿信标上面它才会停下」），需要统一配置时改写。
