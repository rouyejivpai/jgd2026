## 1. 测试基础设施

- 框架：**GUT**（Godot Unit Test）。从 AssetLib 或 https://github.com/bitwes/Gut 取与引擎匹配的版本（Godot 4.7 → GUT 9.7.x，当前 9.7.1），放入 `addons/gut/`，在项目设置 Plugins 中启用。
- 目录：`tests/unit/`（纯模拟核心，不依赖场景）、`tests/integration/`（整关 headless 跑完）。
- 命令（在 `godot/` 目录）：

```bash
H:/Godot_v4.7.2/Godot_v4.7.2-stable_win64_console.exe --headless --path . -s addons/gut/gut_cmdln.gd -gdir=res://tests -ginclude_subdirs -gexit
```

- 数据离线校验（每次改 `data/` 后必跑）：

```bash
python tools/validate_data.py
```

- 测试辅助 `tests/helpers/sim_factory.gd`：`make_world(level_id, deploy: Dictionary, rules_override: Dictionary) -> SimWorld`、`run_until_end(world, max_seconds) -> int(BattleResult)`、`run_steps(world, n)`、`make_unit(def_id, faction, pos, rules) -> SimUnit`、`tiny_grid(w, h, blocked)`.

## 3. 集成测试（`tests/integration/test_levels_headless.gd`）

对每关：
1. `make_world(level, recommended_deploy, slot 初始 rules)` → `run_until_end(60s)` → **断言 WIN**（第四关因算法待验证，允许标记 `pending` 但必须打印实际结果）。
2. 用 JSON `verification.expected_fail` 对应的配置（在测试中硬编码一个明确错误部署，如第二关前后排倒置、第七关前排开启追击并把全部单位放在 y=6）→ 断言 LOSE 或在 60s 内未胜。
3. 1× 与 2× 分别运行到结束，`state_hash` 与结果一致。
4. 第七关专项：断言至少发生一次 `target_changed` 事件发生在某个 `unit_died` 之后（"目标死亡后重新选敌"）；敌人提前全灭时 `threat_cleared` 为真且在 20.0s 胜利。
5. 第三关专项：守卫 W1/W2 在诱饵存活且可见期间 `current_target` 恒为诱饵 id（逐步断言）。
6. 第五关专项：至少放置一次爆炸；快速形态从未在爆炸中受伤（推荐解下）。
7. 第六关专项：三具残骸首次锁定均为承伤；祭司死亡时远射的 `current_target` 曾为祭司。
