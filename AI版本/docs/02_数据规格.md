# 《人工神灵》Demo 数据规格（JSON Schema 说明）

版本 1.1 ｜ 2026-10-05 ｜ 配套：`01_程序架构.md` §5–§6、`07_第二阶段架构与数据变更.md` §11；枚举字符串与 `godot/scripts/core/sim_types.gd` 一一对应。

1.1 修订（第二阶段 P0）：删除 `rewards.unlock_slots`（Q-010）；并入 `biomes.json`（§8，Q-033）与 `progression.json`（§9，Q-009）；`recommended_deploy` 与 `slots[].rules` 合并为 `recommended`（§5，07 §2）；新增 `DEPRECATED_FIELD` 校验（§7）。

通用约定：
- 所有文件 UTF-8，无 BOM。坐标一律 `[x, y]` 整数，**左下为原点，y 向上**。
- 枚举值为小写 snake_case 字符串，加载时转换为 `SimTypes` 枚举；未知值 = 数据错误。
- "必填"字段缺失 = 数据错误（`push_error`，禁止进入关卡）。可选字段默认值在表中给出。

## 1. `data/units.json`

```json
{
  "schema_version": 1,
  "units": {
    "<unit_id>": { ...UnitDefinition }
  }
}
```

### UnitDefinition

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `display_name` | string | ✓ | 面板显示名 |
| `kind` | `"unit"` / `"structure"` | ✓ | 建筑不移动、不攻击、不计入全歼、不计入"己方全灭" |
| `faction_default` | `"ally"` / `"enemy"` / `"neutral"` | ✓ | 关卡 SpawnDef 可覆盖 |
| `max_hp` | number > 0 | ✓ | |
| `attack` | number ≥ 0 | ✓ | 每次普通攻击伤害 |
| `attack_speed` | number ≥ 0 | ✓ | 次/秒；0 = 不能攻击 |
| `move_speed` | number ≥ 0 | ✓ | 格/秒；0 = 不能移动 |
| `vision` | number ≥ 0 | ✓ | 感知半径（格，圆形） |
| `range` | number ≥ 0 | ✓ | 攻击射程（格，中心点欧氏距离） |
| `traits` | string[] | 可选 `[]` | 引用 `traits.json` 的 id |
| `allowed_actions` | string[] | ✓ | 该形态可被玩家配置的行为类型集合（见 §3 ActionDef.type） |
| `default_rules` | RuleDef[] | ✓ | 敌方默认规则（可空数组）。第二阶段起新放置的己方单位一律空指令，己方形态的该字段不再使用（07 §2） |
| `cost` | 正整数 | 己方形态必填 | 第二阶段（07 §4.1）：free 关出场扣除的预算。己方形态 = `faction_default: "ally"` 且 `kind: "unit"`；临时单价基础攻击 3、承伤 4、快速 3、远射 4（08 ②） |
| `public_rule_text` | string | 可选 `""` | 敌人面板顶部一句话公开规则（例如第七关："先攻击射程内最近的分裂体，否则冲向转运点"）；为空时 UI 由规则列表自动生成整句 |
| `description` | string | 可选 | 形态说明/世界观一句话 |
| `visuals` | object | ✓ | 见下 |

`visuals`：
| 字段 | 类型 | 说明 |
|---|---|---|
| `sprite` | string | `res://assets/sprites/units/<id>.png`（256×256，透明背景） |
| `portrait` | string | `res://assets/sprites/portraits/<id>.png`（512×512） |
| `projectile` | string | `res://assets/sprites/projectiles/<name>.png`；近战单位填 `"none"`（表现为冲刺挥击） |
| `scale` | number | 显示缩放，默认 1.0（建筑可 1.3） |
| `light_color` | string | 十六进制 `"#RRGGBB"`，该单位 PointLight2D 颜色 |
| `hit_sfx` / `attack_sfx` / `death_sfx` | string | `assets/audio/sfx/` 下文件名（不含路径） |

## 2. `data/traits.json`

```json
{
  "schema_version": 1,
  "traits": {
    "<trait_id>": {
      "type": "delayed_blast",
      "public_text": "面板上公开给玩家的说明",
      "params": { ... }
    }
  }
}
```

### type = `delayed_blast` 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `damage` | number | ✓ | 对范围内敌对单位伤害 |
| `radius` | number | ✓ | 爆炸半径（格） |
| `delay` | number | ✓ | 放置到爆炸的秒数（模拟时间） |
| `cooldown` | number | ✓ | 两次放置的最小间隔 |
| `selector` | string | 可选 `"farthest"` | 选目标规则 |
| `filter` | string | 可选 `"unit"` | 候选过滤 |
| `range` | number | 可选 = vision | 落点距施放者最大距离 |
| `first_delay` | number | 可选 `0` | 开战后首次可放置前的额外等待（给玩家观察时间） |

Demo 只实现这一种 type。加载到未知 type → 数据错误。

## 3. 规则（RuleDef）——敌我、默认、玩家配置、推荐阵型共用

```json
{
  "enabled": true,
  "condition_mode": "all",
  "conditions": [ { "type": "enemy_in_range" } ],
  "target": { "selector": "nearest", "filter": "unit" },
  "action": { "type": "attack" }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `enabled` | bool | 可选 `true` | 第三阶段（10 §5.2）：编辑器不再显示启用勾选，UI 写出恒为 `true`；读档时玩家配置的 `false` 视为 `true` 并在下次保存写回；推荐阵型中的 `false` 条目摆放时略去（Q-059，评估器本就跳过）。字段与评估器不变（敌人数据仍可用） |
| `condition_mode` | `"all"` / `"any"` | 可选 `"all"` | 空 `conditions` = 无条件。UI（10 §5.3）：玩家条件 ≤ 2，「与 / 或」切换仅两条件时显示，少于两条时写 `all`；整句以「且 / 或」连接 |
| `conditions` | ConditionDef[] | ✓（可空） | |
| `target` | TargetDef | 行为需要目标时必填 | `idle`/`retreat`/`follow_route` 可省略 |
| `action` | ActionDef | ✓ | |

### ConditionDef

| `type` | 参数 | UI 整句模板 |
|---|---|---|
| `always` | — | "始终" |
| `self_hp_below` | `ratio` (0–1) | "自身生命低于 {ratio%} 时" |
| `enemy_visible` | — | "视野内存在敌人时" |
| `enemy_in_range` | — | "存在射程内敌人时" |
| `target_distance` | `op` (`"<"`/`">"`), `value` | "目标距离{op}{value}格时" |
| `retreat_possible` | `threat_radius`(可选=vision), `search_depth`(可选 3) | "附近有威胁且存在退路时" |
| `at_beacon`（P2） | `beacon`（信标编号 "1"、"2"…；第三阶段起，旧字母 A–H 按 1–8 读取并报 DEPRECATED_FIELD） | "到达信标 {beacon} 时"。持续成立型：距该信标格中心 ≤ 0.35 格；信标不存在 = 不成立（BEACON_MISSING） |

### TargetDef

| 字段 | 值 | 说明 |
|---|---|---|
| `selector` | `nearest` / `farthest` / `lowest_hp` / `first_seen` | |
| `filter` | `any` / `unit` / `structure` | 可选，默认 `any` |

### ActionDef

| `type` | 参数 | 需要目标 | UI 整句 |
|---|---|---|---|
| `idle` | — | 否 | "原地待机" |
| `attack` | — | 是 | "攻击{目标}" |
| `chase_attack` | — | 是 | "追击并攻击{目标}" |
| `chase` | — | 是 | "追击{目标}（不攻击）" |
| `retreat` | `threat_radius`(可选=vision), `search_depth`(可选 3) | 否 | "远离威胁撤离" |
| `follow_route` | `route_id`(必填), `loop`(可选 false) | 否 | "沿路线「{route_name}」前进" |
| `follow_beacons`（P2） | `mode`（`once`/`loop`/`pingpong`，可选 once）, `from`（信标编号，可选 "1"；旧字母同上） | 否 | "从信标 {from} 起沿我的信标前进（单程/循环/往返）"。行为见 07 §3.2 |
| `wait`（P2） | `seconds`（0.5–30，必填） | 否 | "原地等待 {seconds} 秒"。边沿触发一次性，见 07 §3.4 |

P2 的 `at_beacon`、`follow_beacons`、`wait` 是每个单位都有的通用工具，**不受**关卡 `allowed`、解锁与形态 `allowed_actions` 限制（Q-047）。信标存在玩家配置 / `recommended.units[].beacons` 中：`[{ "id": "1", "cell": [x, y] }]`。第三阶段（10 §6.3）：id 为正整数字符串，无 8 个上限（`SimTypes.BEACON_SOFT_CAP = 64` 仅防呆），删除后不重排、新信标取当前最大编号 + 1；校验码 `BEACON_MISSING`、`BEACON_ON_BLOCKED`、`BEACONS_EMPTY`（均阻止开始）。

整句拼装规则：`"{条件}，{行为}"`，目标词 = `"{selector 词}{filter 词}"`，如"最近的敌人"、"最远的敌方单位"、"首个进入视野的敌人"、"最低生命的建筑"。

## 4. `data/commands.json`（指令目录，第三阶段 10 §5.1；取代已删除的 `presets.json`）

```json
{
  "schema_version": 1,
  "actions":    [ { "id": "attack", "unlock_key": "preset.attack_nearest_in_range", "cost": 0, "player": true }, ... ],
  "conditions": [ { "id": "always", "unlock_key": "", "cost": 0 },
                  { "id": "target_distance", "unlock_key": "preset.retreat_when_close", "cost": 0, "defaults": { "op": "<", "value": 3 } }, ... ],
  "selectors":  [ { "id": "nearest", "unlock_key": "" }, ... ],
  "filters":    [ { "id": "any", "unlock_key": "" }, ... ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | 字符串 | ✓ | 必须是 `SimTypes` 可解析的行为 / 条件 / 选敌 / 目标类型值；同类不重复 |
| `unlock_key` | 字符串 | 可选 `""` | 复用 progression / 关卡 rewards 的 `preset.*` 解锁键；空 = 始终可用（只允许信标 / 到点 / 等待类与 `always`，Q-047）。非空键必须出现在 `progression.initial_unlocks.presets` 或某关 `rewards.unlock_presets` 中（加载与 validate 校验） |
| `cost` | 非负整数 | 可选 0 | 指令 Cost（10 §5.5）：指令 Cost = Σ 每条指令 (action.cost + Σ condition.cost)；单位总 Cost = 形态 `cost` + 指令 Cost，free 关预算校验 `BUDGET_EXCEEDED` 按总 Cost。选敌 / 目标类型不计 Cost。**本阶段全部为 0**（决策 ⑧），数值另派任务 |
| `player` | bool | 可选 `true`（仅 actions） | `false` = 不进玩家菜单（`follow_route`：预设路线只给敌人数据用） |
| `defaults` | 对象 | 可选 | 实施方追加（Q-060）：新建该条件 / 行为时的参数（原取自同类预设），如 `target_distance` `{ "op": "<", "value": 3 }`、`self_hp_below` `{ "ratio": 0.3 }` |

- **数组顺序 = 菜单顺序 = 默认项**（第一项为默认）：条件默认「始终」，目标选择默认 `nearest`、目标类型默认 `any`（取各自列表中首个可用项）。
- 「添加指令」只弹出**行为列表**（`player` ∧ 已解锁 ∧ 本关 `allowed` ∧ 形态 `allowed_actions`；信标 / 等待不受 allowed 限制），选中即在末尾新增一行：条件「始终」，参数取默认，`follow_beacons` 起点取本单位第一枚信标，`wait` 秒数取 `WAIT_MIN_SECONDS`。不再有预组合指令。
- 下拉可用性：解锁键已解锁 ∧（受限类型）本关 `allowed` ∧ 对应类型解锁列表（`unlocks.conditions / selectors / actions`）；目标类型只看解锁键。当前值即使不可用也保留在下拉里。
- 标签与整句模板沿用 `strings.json` 的 `names.*`、`action_text / condition_text / selector_text / filter_text`。
- `progression.json` 与关卡 `rewards.unlock_presets` 不改；`presets.json` 与 `PresetDef` 已删除（P1 末），存在 `presets.json` 时 validate 报错。

## 5. `data/levels/level_XX.json`

```json
{
  "schema_version": 1,
  "id": "level_07",
  "index": 7,
  "title": "守住归途",
  "subtitle": "保护目标与目标失效后的持续执行",
  "biome": "transit_node",
  "background": "res://assets/backgrounds/level_07.png",
  "bgm": "battle_01",
  "seed": 7,
  "grid": { "width": 13, "height": 9, "blocked": [] },
  "deploy_zone": { "rect": [1, 2, 3, 6], "exclude": [[2, 4]] },
  "roster": { "mode": "fixed", "budget": 0, "available_forms": null, "max_units": 3, "min_units": 3, "fixed_slots": [ ...SlotDef（不含 rules） ] },
  "initial_units": [ ...SpawnDef ],
  "routes": { "<route_id>": { "name": "显示名", "points": [[x,y], ...] } },
  "allowed": { "conditions": [...], "selectors": [...], "actions": [...] },
  "objectives": { "win": [...], "lose": [...], "objective_text": "保护转运点存活 20 秒" },
  "briefing": { "dialogue": [ { "speaker": "doll", "text": "..." } ], "mechanic_hint": "..." },
  "hints": [ "第1层", "第2层", "第3层", "第4层（可写推荐部署文字；看过后提示按钮变为「推荐阵型」）" ],
  "fail_feedback": { "<lose objective id>": "文本", "default": "..." },
  "recommended": {
    "units": [ { "slot": "slot_bulwark", "form": "bulwark", "pos": [3, 4], "rules": [ ...RuleDef ], "beacons": [] } ]
  },
  "rewards": { "unlock_forms": [], "unlock_presets": [], "unlock_conditions": [], "unlock_selectors": [], "unlock_actions": [], "unlock_level": "level_08", "story_id": "ch1_l7_outro" },
  "verification": { "expected_win": "...", "expected_fail": "...", "alternatives": "...", "risks": "..." }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `grid.blocked` | ✓ | 障碍格列表；其余格可行走 |
| `deploy_zone.rect` | ✓ | `[x0, y0, x1, y1]` 含边界；`exclude` 可选，列出 rect 内禁放格；也可用 `cells` 直接列格（与 rect 二选一） |
| `roster` | ✓ | 出场（07 §4.1，P3 起取代 `slots`；旧 `slots` 出现 = `DEPRECATED_FIELD` 错误）。`mode`：`"fixed"` = 固定槽位（第一阶段行为，用 `fixed_slots`）/ `"free"` = 自主选择形态；`budget`：free 关 Cost 预算（正整数）；`available_forms`：可出场形态（null = 全部己方形态），再与全局解锁 `unlocks.forms` 取交集；`max_units` / `min_units`：出场人数上下限（1 ≤ min ≤ max）；`fixed_slots`：仅 fixed。free 关的推荐阵型必须放得进预算与人数上限（加载校验）。现有关卡：第七关 fixed；其余 free，`available_forms` = 第一阶段该关槽位的形态、`max_units` = 原槽位数（Q-050），预算见 CHANGELOG（Q-049） |
| `roster.fixed_slots[]` | fixed 必填 | `{ "id": "slot_bulwark", "unit": "bulwark", "fixed": true, "editable_rules": true }`。`fixed=true` 表示本关固定形态；`fixed=false` 时 `unit` 为默认，玩家可换成任何已解锁形态。**新放置单位的初始指令一律为空**（07 §2，用户 2026-10-05 已定）；`units.json` 的 `default_rules` 只用于敌人。旧字段 `rules` 已废弃：出现时报 `DEPRECATED_FIELD` **提醒**并被忽略（待资源/数据清理时删除）。若存档中已有该关该槽位配置，则存档优先 |
| `recommended` | ✓ | 「推荐阵型」（07 §2）。`units[]` 每项：`slot`（fixed 模式）或 `form`（free 模式，P3 起；两者都给时以 `roster.mode` 为准）、`pos` 部署格、`rules` 推荐指令（RuleDef 数组，可含 `"enabled": false`）、`beacons` 信标（`[{ "id": "1", "cell": [x, y] }]`，机制见 07 §3、10 §6.3）。提示 4 层看完后提示按钮变为「推荐阵型」，确认后把部署、指令、信标一并覆盖到当前配置并校验。替代第一阶段的 `recommended_deploy` 与 `slots[].rules`（第一阶段的槽位初始指令已原样迁入此处） |
| `initial_units[]` | ✓ | SpawnDef：`{ "id": "A", "unit": "raider", "faction": "enemy", "pos": [10,1], "tags": [], "rules": [...可选覆盖], "counts_for_annihilate": true, "display_name": "可选覆盖" }`。己方建筑（如保护对象）也在此列出，`faction: "ally"` |
| `routes` | 可选 `{}` | 路点序列；相邻路点须四连通可达（加载校验） |
| `allowed` | ✓ | 本关允许玩家使用的条件/选敌/行为类型；与解锁取交集 |
| `objectives.win[]` / `lose[]` | ✓ | 每条 `{ "id": "...", "type": "...", ...参数 }`；至少各一条；类型见 01 文档 §6.9。P4（07 §9）起 win 另可用 `reach_zone`（`target`: spawn id 或 `"any_ally"`、`cells`、可选 `count` 默认 1：任意己方单位满 count 名到达即胜）与 `escort`（`target`: 己方可移动初始单位、`cells`：该单位存活到达即胜；关卡必须另有 lose `unit_dead` 指向同一目标）；`any_ally` 不能用于 lose |
| `modifiers` | 可选 `[]` | P4（07 §7）静态关卡加成：`{ "target": "spawn:<id>" / "form:<形态>" / "faction:<阵营>", "stat": "max_hp/attack/attack_speed/move_speed/vision/range", "mul": 1.0, "add": 0 }`，构建世界时按顺序一次性应用（值 × mul + add），无时效、叠层、驱散；面板显示"160（+32 关卡加成）" |
| `initial_units[].overrides` | 可选 `{}` | P4（07 §9）属性覆盖 `{ "vision": 5 }`（键同 modifiers.stat），在 modifiers 之后以"覆盖"方式应用 |
| `briefing` | ✓ | P5 起只含 `mechanic_hint`（本关机制提示卡，开始剧情之后显示；也列在"机制说明"顶部）。旧 `briefing.dialogue` = `DEPRECATED_FIELD` 错误：战前对白写入 `data/stories/<level_id>_intro.json` |
| `hints` | ✓ | 恰好 4 条，由浅到深 |
| `fail_feedback` | ✓ | 键 = lose 条目 id；必须有 `default` |
| `rewards.unlock_*` | ✓ | 空数组表示无。`unlock_slots` 已删除（Q-010；出场数量改由第二阶段 Cost 预算决定）；`rewards.story_id` 已删除（P5，`DEPRECATED_FIELD`：剧情按 `<level_id>_intro / _win / _lose` 约定查找） |
| `verification` | ✓ | 给试玩人员，不进游戏 |
| `summary` | 可选 `""` | 第三阶段预留（10 §3.1）：关卡特征一句话，给章节地图详情面板；空则回退 `subtitle`。本阶段不填（决策 ⑫） |

### 存档中玩家配置片段（SaveManager，存档版本 4；2 = 07 §4.2 单位列表，3 = stories_seen，4 = 信标数字编号）

```json
"level_configs": {
  "level_02": { "next_uid": 3, "units": [
    { "uid": "u1", "form": "bulwark", "pos": [3, 3], "rules": [ ...RuleDef ], "beacons": [] },
    { "uid": "u2", "form": "striker", "pos": [1, 2], "rules": [ ... ], "beacons": [ { "id": "1", "cell": [5, 6] } ] }
  ] },
  "level_07": { "next_uid": 1, "units": [
    { "uid": "slot_bulwark", "slot": "slot_bulwark", "form": "bulwark", "pos": [3, 4], "rules": [ ... ], "beacons": [] },
    { "uid": "slot_lancer",  "slot": "slot_lancer",  "form": "lancer", "rules": [ ... ], "beacons": [] }
  ] }
}
```
- free 关：uid 在部署阶段分配 u1、u2…，递增不复用（`next_uid`）；收回 = 删除该单位并返还 Cost，只保存已部署单位。己方模拟 id = ALLY_ID_BASE + (uid 编号 − 1)。「推荐阵型」覆盖全部单位并从 u1 重新分配。
- fixed 关：uid = 槽位 id，每个槽位都保存指令与信标，未部署无 `pos`；模拟 id = ALLY_ID_BASE + 槽位序号。
- v3 → v4 迁移（10 §6.3）：各关配置中的信标 id 与 `at_beacon.beacon` / `follow_beacons.from` 的旧字母 A–H 改为 "1"–"8"，其余不动。
- v1 → v2 迁移：fixed 关直接改写；free 关按旧槽位顺序给已部署者分配 u1…，形态由槽位名推出；无法转换或未部署而被丢弃的条目原样保留在 `legacy_v1`，该关配置标记 invalid（`SAVE_MIGRATION_FAILED`），不删除。`unlocks.slots` 删除。

## 12. `data/ui_motion.json`（第三阶段 P8，10 §1.5）

UI 动效参数（只影响表现层，不进存档、不影响模拟哈希）。顶层每个对象是一档；`"extends": "<档名>"` 以另一档为底、只写不同的项（浅合并，嵌套对象整体替换）。

| 档 | 用途 |
|---|---|
| `button` | 通用按钮档：SceneRouter 启动时装上的钩子，会把它自动挂到之后进入场景树的全部 Button / OptionButton。不挂的：flat 按钮、CheckBox / CheckButton / MenuButton / ColorPickerButton、带 meta `no_motion` 的按钮 |
| `button_menu` | 主界面大按钮（`main_menu.gd` 显式指定）：选中让位与焦点跟随鼠标 |

字段（每档）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `hover_in` / `hover_out` / `press` / `release` | `{duration, trans, ease}` | 状态过渡；duration 为秒（建议 ≤ 0.25，超过时 validate 给提醒）；trans ∈ linear / sine / quad / cubic / quart / quint / expo / circ / back / elastic / bounce / spring；ease ∈ in / out / in_out / out_in |
| `sweep` | `{duration, trans, ease, band_px, slant, strength}` | 从普通态进入选中时，金色描边上扫过一次的斜向光带 |
| `breathe` | `{period, amplitude}` | 选中时金色亮度的呼吸 |
| `press_scale` | 数，[0.9, 1] | 按下时以中心缩放（切换按钮的按下常态不缩放） |
| `hover_lift` / `hover_boost` | 非负数 | 选中时底板（非金色部分）提亮 / 金色加强 |
| `hover_nudge_px` | 非负数 | 选中时按钮背景与文字一起右移的像素 |
| `text_hover_lighten` / `text_press_darken` | 非负数 | 文字颜色提亮 / 压暗比例 |
| `gold_mask` | `[低, 高]` | 金色判定：r − b 的平滑阶跃区间 |
| `focus_follows_mouse` | bool | 悬停即取焦点（Q-072；只用于菜单类界面） |

代码级总闸 `UiKit.motion_enabled`（截图 / 比对工具 `--no-motion`），本阶段不做设置项。
