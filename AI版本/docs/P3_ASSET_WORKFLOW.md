# 第三阶段资源制作流程（P5验证后）

2026-10-05：用户确认P5实机验收无误，并指定以后统一交全部界面整图，判断无误后才实际拆分；制作前先考虑复用，保持素材一致。

## 已走通的流程

控件与状态清点 → 真实游戏字体/色板和manifest契约 → 整图布局 → 用户反馈迭代 → 用户批准V5 → 按批准画面拆分 → RGBA/四态/九宫格/文字绑定 → 资源侧从manifest回拼 → 程序apply_ui_manifest生成主题与布局 → 实机截图与ui_diff → 用户目视通过。

P5现有报告最终差异：主界面0.1537%、错误态0.3192%、设置浮窗0.6552%（三者均通过；错误态精确值以报告为准）。设置仅忽略动态日志路径；面板和控件不屏蔽。比对使用通道容差2/255、文字区±1px栅格位移匹配。资源侧回拼不代替实机验收。

## 后续统一流程

1. 从当前程序与数据核对控件、状态、尺寸、真实文字来源；不凭印象设计新业务入口。
2. 查已批准common和既有图标/头像/精灵，登记能直接复用、仅需调制/九宫伸缩、确需新增的内容。复用资源不重绘、不悄悄修改尺寸或颜色源文件。
3. 沿用低饱和灰紫、骨白、炼金金和少量暗红；边框轻量，减少ASCII式装饰。游戏名等关键艺术字独立登记，普通标题/正文只用游戏字体。
4. 一次完成所有剩余界面和关键状态的1920×1080整图，另附场景完整提案及3840×1080章节宽图。用户统一审阅期间不导出新切片/manifest。
5. 用户判断无误后冻结坐标和样例状态。只拆新增图像；既有素材用引用或原样迁移至common，SHA保持一致。普通文字保留Label，按钮纹理无普通文字。
6. 交四态、真实alpha、九宫格保护边距、字体与strings绑定、按P5约定配对的下拉/滑条、manifest和预览。艺术字作为独立file/id/rect；状态与样例值不写玩家配置。
7. 从交付manifest回拼，报告严格/容差/字形豁免指标与未过线情况。HDR局内按线性光合成，菜单/章节按sRGB；程序方仍须按实际视口验证。
8. R4按现有玩法矩形和blocked分离base与低矮障碍，核对cells/anchor/size并检查回贴<1%；不改关卡几何来迁就绘画。
9. 程序方P6/P7接入、逐界面实机diff、多分辨率和既有功能回归，最后用户目视验收。按已验证的接口接线，资源方不替代功能代码。
10. 每次任务结束删除临时脚本、缓存和测试图，保留生产原图、完整设计、来源记录和测试结论。

## P5的具体经验

普通字形由真实字体排版，不能靠模型“仿字体”。焦点复用hover；下拉值与箭头分层；滑条按填充满宽/把手公式画。九宫保护曲线与角点；有1px描边留白时按视觉rect使用。半透明画面的合成空间必须一致，遇到差异先检查HDR与alpha，再检查几何，不能整块屏蔽面板过线。
