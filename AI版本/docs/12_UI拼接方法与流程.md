## 2. manifest 约定（10 §1.2 + 增补，P5 实测）

| 项 | 约定 |
|---|---|
| 顶层 | `schema_version: 1`、`screen`、`design_size: [1920, 1080]`、`elements[]` 按**从后往前**的绘制顺序 |
| `rect` | 全局设计坐标 `[x, y, w, h]`；铺满整个设计画布的元素（如背景、遮罩）运行时 cover 整个视口 |
| `text_rect` | 元素**内部**坐标；按钮文字区 → 主题 content_margin |
| `kind` | `image`、`icon` → TextureRect；`ninepatch` → PanelContainer（主题变体，StyleBoxTexture）；`button` → Button（四态 StyleBoxTexture）；`text_style` → Label；`toggle` → TextureButton（`states: {on, off}`）；`slider` 不单独使用，见下 |
| 文件路径 | 相对当前 manifest 目录，可 `../common/`，必须落在 `assets/ui/` 内 |
| 九宫格 | `ninepatch: [左, 上, 右, 下]`，即 texture_margin；视觉 rect 可能比名义控件外扩 1 px 留白，**照 manifest rect 画，不要再裁** |
| 文字 | 切片不含普通文字；文字由字体渲染，内容取 TEXT_BINDINGS 的 strings key。key 为空的静态文字要补键（P5 补了 `ui.game_subtitle`），动态值由脚本填 |
| 字体 | `NotoSerifSC` / `NotoSerifSC-Bold` / `Cinzel` → `assets/fonts/` 下真实字体文件 |
| 状态 manifest | 如 `error_manifest.json`：只取主 manifest **没有**的元素（标 `error_only`，运行时按条件建出）和按钮禁用字色 |
| 下拉 | `dropdown_<名>`（button）+ 显示值 `<名>_value`（text_style）配对，值的字体与位置并入下拉按钮（布局里值元素标 `merged_into`）；箭头是独立 `icon`；弹出列表用下拉 normal / hover 贴图（主题变体 `<screen>__dropdown_<名>__popup`） |
| 滑条 | 轨 `slider_<键>_track`（ninepatch）+ 填充 `slider_<键>_fill`（ninepatch）+ 把手 `slider_<键>_grabber`（icon）三层，上面叠透明 HSlider 接收输入。满宽 = 轨右端 − 填充左端；填充宽 = floor(满宽 × 值)；把手 x = floor(填充末端 − 把手宽 / 2)；把手状态图按 `slider_grabber_<normal/hover/pressed/disabled>.png` 在同目录取 |
| 焦点 | TEXT_BINDINGS 约定"focus 复用 hover"：主题 focus 样式为空，有焦点时 normal 临时换成 hover（`UiKit` 已实现） |

发现新的格式问题：写 `docs/QUESTIONS.md`（下一个编号），在 10 §1.2 增补里加一条，并在 PROGRESS 中写明"需资源方修订 R0 规范"。**不要为迁就切片去改设计，也不要在代码里写补偿用的像素数字**；必要时让资源方改 manifest。

## 3. 拼接步骤（每个界面一遍）

### 3.1 生成主题与布局
```
python tools/apply_ui_manifest.py <screen> [<screen> ...]
```
- 先校验（kind、id 唯一、rect 在设计尺寸内、文件存在且在 assets/ui 内、按钮四态齐全、九宫格边距 ≤ 贴图尺寸），有错不写任何文件、exit 1。
- 产物（**程序不手改**，改了也会被下次生成覆盖）：
  - `godot/assets/themes/ui_<screen>.tres`：每个 button / text_style / ninepatch 元素一个类型变体 `<screen>__<id>`
  - `godot/data/ui_layout/<screen>.json`：每个元素的 kind、rect、text_rect、align、贴图 res:// 路径、strings key、主题变体名、`error_only` / `merged_into`
  - 引用贴图的 `.import`：Lossless、无 mipmap（首次接入先跑一次 `--import` 生成 .import，再运行本工具，再 `--import` 一次）
- 新的 kind 组合或约定（例如 HUD 的卡片列表）需要扩展本工具时：在工具内加规则、在本文档 §2 记一行、在 QUESTIONS 留档。

### 3.2 改界面脚本
参照 `scripts/screens/main_menu.gd`（静态页）与 `scripts/ui/settings_overlay.gd`（浮窗 + 动态控件）：
```gdscript
const SCREEN: String = "<screen>"
const NODE_NAMES: Dictionary = { "btn_start": "StartButton", ... }   # 元素 id → 现有节点名（保持测试 / 工具能找到）
nodes = UiKit.build_from_layout(self, SCREEN, NODE_NAMES)           # 设主题、按布局顺序建节点、文字取 key
# …只做文字 / 数值绑定与功能接线（pressed.connect 等）…
resized.connect(_layout)
func _layout() -> void:
	UiKit.relayout(SCREEN, nodes, size)                             # 唯一的摆放入口
```
- `UiKit.layout_rect(screen, id, 视口尺寸)` 是**唯一**的设计 → 屏幕换算（设计画布居中取整；铺满画布的元素 cover）。动态元素（填充宽、把手位置、列表项）也只用它取基准矩形再算。
- 界面脚本里**不出现像素数字**（10 §10 铁律 1）；中文只走 strings.json（`python tools/check_ui_literals.py`）。
- **保持节点名与公开方法不变**，功能代码路径不改（换皮不改功能）。原 `.tscn` 里程序化占位节点删掉，场景只留根节点 + 脚本（见 `scenes/screens/main_menu.tscn`）。
- 第三阶段 P0–P4 的占位布局常量在 `UiKit` 顶部（HUD、章节地图等）。换皮后该界面不再用的常量删掉；仍被别处用的（如 `TOP_BAR_HEIGHT` 与 `Playfield` 公式相关）先保留并在 QUESTIONS 说明。
- 错误态 / 条件元素：`build_from_layout` 跳过 `error_only`，由脚本按条件 `UiKit.node_for(e)` 建出（见 `main_menu.gd::_build_error_state`）。

### 3.3 截图
在 `tools/take_screenshots_impl.gd` 给该界面加一个 `--screen=<名>` 模式（参照 `_ui_shot` / `_chapter_shots`）：
- 把动态内容设成**设计图上的样例状态**（数值、开关、选中项、焦点、错误态等），不写存档、不应用显示设置，结束后恢复；
- 输出 `docs/screenshots/ui_diff/<screen>_actual.png`。
```
Godot_v4.7.2-stable_win64_console.exe --path . -s res://tools/take_screenshots.gd -- --out=../docs/screenshots/ui_diff --screen=<名>
```
需要真实窗口（不要 `--headless`）。**P8 起截图一律加 `--no-motion`**（动效冻结在静止态，截图旁写 `.meta.json`），比对时 `ui_diff.py` 也加 `--no-motion` 校验；按钮动效已由 `UiKit` 自动挂到全部按钮（P8-4），界面脚本不用处理；确实不要动效的按钮设 meta `no_motion`，菜单类大按钮可显式用 `UiKit.attach_button_motion(b, "button_menu")`。多分辨率：加 `--size=2560x1080`、`1920x1200`、`1280x720`，输出到 `ui_diff/<尺寸>/`，目视检查居中、无截断、无重叠。

### 3.4 比对
```
python tools/ui_diff.py --design assets/ui/<screen>/design.png --actual ../docs/screenshots/ui_diff/<screen>_actual.png \
    --manifest assets/ui/<screen>/manifest.json [--context-manifest assets/ui/<下层界面>/manifest.json] \
    [--ignore <元素id> x,y,w,h ...] --out ../docs/screenshots/ui_diff/<screen>_diff.png --report ../docs/screenshots/ui_diff/<screen>_report.json
```
- 三档指标：**严格**（任一通道差 > 0）、**容差**（> `--tol`，默认 2/255，排除 `--ignore`）、**最终**（文字区允许 ±1 px 位移匹配，吸收字形栅格化差异）。通过 = 最终 ≤ 2%。
- 差异图：红 = 不同，黄 = 文字豁免，蓝 = 忽略区。
- `--ignore` 只用于**真正的动态内容**（如日志路径），在 PROGRESS 中逐项写明；不得忽略面板、控件、贴图来过线。
- 浮窗类设计图含下层界面时，用 `--context-manifest` 把下层的文字区也纳入文字豁免。
- 未过线时的排查顺序：看差异图红块 → 对照 §5 常见原因 → 改布局 / 脚本 / 工具，**不改设计图、不改切片**；属于切片问题的反馈资源方。

### 3.5 测试、记录、提交
- 测试：为该界面加或改集成测试（参照 `tests/integration/test_ui_layout.gd`）：节点位置 = `layout_rect`、文字取 key、主题变体、状态元素出现条件、动态控件随数值变化；原有功能测试必须照旧通过（只允许改节点类型断言，例如 CheckButton → TextureButton）。
- 全量：GUT 普通 + 严格告警（`cp tools/strict_warnings.cfg override.cfg` → 跑 GUT → 删除 `override.cfg`）、`validate_data.py`、`check_ui_literals.py`、`run_playtests -- --check`。
- 记录：PROGRESS（指标表、截图路径、忽略项、残差说明、"待用户目视"）、CHANGELOG（新生成的主题 / 布局文件、strings 新键、渲染或导出设置变化）、QUESTIONS（格式问题）。
- **每个界面一次提交**（任务包 P6 要求），一并提交该界面的 `assets/ui/<screen>/`（运行依赖）；资源方对工具 / 文档的其他未提交改动不要带上。

## 5. 常见原因与已知坑

| 现象 | 原因 / 处理 |
|---|---|
| 半透明区域大面积偏色（遮罩、半透明按钮底） | 项目开启 HDR 2D，线性空间混合；设计按 sRGB 合成。`SceneRouter` 只在战斗场景开 `use_hdr_2d`，菜单类界面关闭（Q-069）。**局内 HUD（R2）仍在 HDR 下**：开工前先定方案（局内比对放宽 / 资源方按线性出图 / 辉光不依赖 HDR 2D），写 QUESTIONS 等架构方 |
| 截图整体偏暗或偏亮 | 截图工具按**当前视口** `use_hdr_2d` 决定是否做线性 → sRGB 转换（`tree.root.use_hdr_2d`），不要按项目设置判断 |
| 条件元素（错误条等）一直显示 | 状态 manifest 的元素必须带 `error_only` 并被 `build_from_layout` 跳过，由脚本按条件建出 |
| 按钮默认态与设计不符 | 设计图常用"首项有焦点 = hover"；确认截图时焦点在哪、TEXT_BINDINGS 的 reference_states |
| 文字区大量红点 | Godot 与 PIL 字形栅格化 / 字距不同，属正常；只要非文字区干净、最终指标过线即可。若整行错位（> 1 px），检查 text_rect、对齐、垂直居中 |
| 下拉 / 滑条与设计差几像素 | 用 §2 的配对与公式，不要用引擎默认的 OptionButton 箭头 / HSlider 绘制 |
| 宽屏下位置偏 | 只能经 `UiKit.layout_rect`；背景类铺满元素自动 cover |
| 换皮界面字号不随"字体大小"设置 | 设计字号固定（Q-071，待定）；未换皮界面仍随设置缩放 |
| 测试偶发失败（剧情已看过、通关进度） | 本机存档会被工具 / 测试写入；测试要在 before_each 里清掉依赖的存档字段并在 after_each 恢复 |
| 九宫格角被拉伸 / 截断 | 按 manifest 视觉 rect 画（含 1 px 留白），texture_margin = manifest ninepatch |

## 8. 以 AI 原生整图为参考的拼接（P6 起，用户 2026-10-05）

R2 起资源方交付的是：批准整图（AI 原生绘制，约 1672×941）+ 重绘的无字切片 + `layout.json`（交付 placement）+ `text_anchors.json`（在批准整图上量出的文字可见边界）。
用户要求：**以批准整图为准**（交付的回拼高度与整图不一致，placement 不可信，但切片本身是对的），**一张一张拼，不批量**。

### 8.1 为什么不能沿用 §3 的逐像素 diff
- 切片是重绘稿，颜色与整图不同（同一控件 RGB 均方差 35–50）；整图文字是 AI 画的字形，不是游戏字体。逐像素比对无论拼得对不对都过不了 2%。
- 因此验收改为**几何一致**：框体位置 / 大小、文字位置与整图一致；颜色与字形差异只报告。

### 8.2 步骤（每个界面）
1. **写 `assets/ui/<screen>/fit_spec.json`**：
   - 参考整图、切片目录、文字锚点文件；
   - 每个元素用哪张切片、哪个文字锚点、字体、对齐、文字区宽 `max_w`、溢出方式 `overflow`、按钮调色 `tint`；
   - 同形框体用 `scale_like` 取同一缩放；界面让出的区域写 `reserved`。
2. **`python tools/ui_fit_reference.py assets/ui/<screen>/fit_spec.json`** → `manifest.json` + `FIT_REPORT.md`：
   - 切片在整图里做**边缘（Sobel）+ alpha 掩码的多尺度匹配**，得到等比缩放后的矩形；
   - 文字按锚点 ink 拟合整数字号并反推 label 矩形，颜色取整图 ink 亮部；
   - 整图坐标按两轴比例换到设计坐标 1920×1080。
3. **`python tools/apply_ui_manifest.py <screen>`**（已支持：状态 `{"file","modulate"}` 调色、`reserved`、`overflow`、`data` 透传）。
4. **界面脚本**：沿用场景节点（节点名、功能不变），按布局摆放（`UiKit.place`：设计 → 屏幕 → 父节点内坐标）；参照 `hud.gd` 的 `_apply_skin / _relayout_skin`。
5. **截图**：`take_screenshots ... --no-motion --text-layer`，另得 `_notext.png`（隐藏全部文字）。
6. **几何验收**：`python tools/ui_geom_check.py --reference <整图> --actual <截图> --notext <_notext.png> --screen <screen>`：
   - 框体：边缘 + 切片掩码，平移搜索，偏移 ≤ 1 px；
   - 文字：实机 ink 取两张截图之差，参考 ink 为锚点；位置（中心，左对齐为左缘）≤ 1 px；宽 > 3 px / 高 > 1.5 px 的差标 ⚠ 字形差，不判失败；
   - 输出 `*_geom.md / .json / _geom_sheet.png`（并排图，上参考下实机）。
7. **校准**：PIL 与 Godot 的字体度量略有差别，再跑 `ui_fit_reference.py <spec> --calibrate <*_geom.json>`：字号 ±1、位置反向修正写回 spec。重复 4–7，直到框体与文字位置全部通过（通常 2–3 轮）。
8. **堆叠内容检验**（用户要求）：`take_screenshots --demo=overflow` 把全部文字槽填超长内容，目视遮罩与页边距；并写进 GUT（参照 `test_scroll_text.gd` 的 HUD 用例）。
9. **交付**：对照图（整图 / 实机上下并排 + 50% 叠图）、几何报告、堆叠截图、多分辨率截图放 `docs/screenshots/ui_geom/<screen>/`；PROGRESS / CHANGELOG / QUESTIONS；用户目视通过后再拼下一张。

### 8.3 文字溢出规则（用户 2026-10-05）
- 每个文字槽都在框体的**内侧文字区**里遮罩（`max_w`：以整图文字中心为轴，到最近的装饰为界，左右对称）。
- 名字、标签、按钮文字、数值超出时**自动往返滚动**（`ScrollText` AUTO）；指令、介绍、提示、任务句等长文本用**滚轮与拖动**（MANUAL，拖动不算点击）。
- 单行左右滚、多行上下滚；遮罩两端渐隐；参数在 `data/ui_motion.json` 的 `scroll_text`。
- 按钮文字超出时由 `UiKit.button_scroll_text` 改为内部代理 Label 绘制（`button.text` 仍是唯一来源）。

### 8.4 已知坑
- **cv2 读不了非 ASCII 路径**：用 `np.fromfile + imdecode`（工具里已处理）。
- **交付 placement 是非等比拉伸**：一律以 `ui_fit_reference.py` 的拟合结果为准，不要用 `layout.json` 的 placement。
- **切片命名与形态 id 不一致**：`card_spitter` = 己方「远射形态」= 形态 id `lancer`（`spitter` 是敌方骨喉）。
- **切片只有一态**：hover / pressed / disabled 用同一贴图调色（`tint`）；整图上部署阶段禁用的按钮画成正常亮度，所以禁用调色取得很轻（#C8C0C8）。
- **Godot 字号只能取整数**：整图字形比例与游戏字体不同，部分文字宽高无法同时落进 ±3 / ±1.5，报告里标 ⚠。
- **`ScrollText.wrap` 之前先让 Label `clip_text`**（否则单行 Label 已被文字撑大），或显式传矩形。
- **find_children 不含内部子节点**（卡面文字、按钮代理是内部节点），递归用 `get_children(true)`。
